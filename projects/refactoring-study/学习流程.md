# 《重构》精读 · 单章学习操作流程（howto）

> 记录「学一章」从抓取到定稿的完整步骤 + 踩过的坑，便于每章复用。
> 已验证：第 2 章按此流程跑通（11 子代理 review → 修订 9 处错误 + 大量漏项 → lint 通过）。

## 1. 一次性准备（首章前做一次）

- 建项目目录 `projects/refactoring-study/` + `README.md`（目录索引 + 体例说明）。
- 用 `AskQuestion` 对齐三件事并固化到 README：
  - **范围/节奏**（先单章跑通 / 整本逐章 / 只挑重点章）
  - **产出形式**（落盘 md / 对话讲解 / 混合）
  - **学习目标**（实战决策 / 体系认知 / 速成）——决定「简洁 vs 细节」取舍。
- 当前已定：单章先跑通 → 落盘 md → 目标「实战决策 + 体系认知」（细节要全）。

## 2. 单章流程（每章重复）

```
Step 1 抓原文      → WebFetch 章节 URL，Read 落地到本地临时文件
Step 2 起草笔记    → 三层结构：① 一页纸决策速查 ② 分节要点 ③ C++ 示例
Step 3 多代理 review → 每个原书小节派 1 个 composer-2.5-fast 子代理逐句比对
Step 4 汇总修订    → 错误必修；关键漏项补；核对子代理误报
Step 5 收尾        → ReadLints；填「沉淀区」；更新 README 状态
```

### 2.1 Step 1 抓原文

- `WebFetch` 章节 URL（如 `https://book-refactoring2.ifmicro.com/docs/chN.html`）。
- 内容会写入临时文件，用 `Read` 通读，确认本章是**理念章**还是**手法/实例章**——决定 C++ 示例是「概念级片段」还是「重构前→后完整对照」。

### 2.2 Step 2 起草笔记（文件名 `第NN章-标题.md`）

三层结构（对应「最短时间抓重点 + 不丢细节」）：

1. **§0 一页纸决策速查**：一句话定义 + 核心口诀 + 决策表（可日常翻阅）。
2. **§1…§N 分节要点**：严格对应原书小节编号，保留关键细节、原书点名的手法、引语、时间锚点。
3. **§ C++ 示例**：被点名手法的最小对照；末尾留「学习沉淀区」（我的复述 / 疑问 / 想补的例子）。

> 写作遵循 `personal-doc-style`：层级编号、金字塔、客观有源、术语展开成直白中文。

### 2.3 Step 3 多代理 review（质量兜底的关键）

- **粒度**：原书有几节就派几个子代理（第 2 章 = 11 个），并行派发（单条消息多个 `Task`）。
- **模型**：`composer-2.5-fast`；`readonly: true`（只 review 不改）。
- **每个子代理的 prompt 必须包含**：
  1. 它负责的笔记小节（给出文件路径 + 具体 `## N` 标题，明确「其它节不要管」）；
  2. **该节原书原文（ground truth，内联完整给全）**；
  3. 固定输出格式：`【漏项】/【错误】/【建议】`，空则写「无」。
- 对易错点可在 prompt 里**点名让它重点查**（如人名/时间/作者归属、C++ 示例语义与语法、决策表归类是否准确）。

### 2.4 Step 4 汇总修订

- 分三类落实：**错误必修 > 关键漏项补 > 次要建议视情况**。
- **核对子代理误报**（见 §3 坑 2）：凡子代理说「原文没有 X」，回真实原文复核再决定，不盲从。
- 修订用 `StrReplace` 逐处改；改完 `ReadLints`。

### 2.5 Step 5 收尾

- `ReadLints` 确认无格式错误。
- README 目录表把本章状态改 ✅。
- 提示用户去「沉淀区」回填，按反馈决定下一章细化/快进。

## 3. 踩过的坑（错误现象 → 根因 → 修复）

### 3.1 大文件单次 Write 失败

- **现象**：`Write` 报 `Expected ',' or '}' after property value in JSON at position 92`。
- **根因**：单次写入内容过大，工具参数 JSON 解析失败。
- **修复**：**分段写**——先 `Write` 主体并在末尾留 `<!-- SENTINEL-NEXT -->` 标记，再用 `StrReplace` 把 sentinel 替换为「下一段 + 新 sentinel」，循环追加。

### 3.2 子代理误报（漏报真错的反面）

- **现象**：子代理报「笔记写了『差团队最后想重写』，但 2.3 原文没有」；实际原文确有该句。
- **根因**：派发时给子代理的是**原文摘要**而非逐字全文，摘要漏句 → 子代理据此误判。
- **修复**：① 尽量给**完整原文**而非压缩摘要；② 汇总阶段对每条「原文没有 X」的结论**回真实原文复核**。本次据此驳回 2 处误报（§3.4 想重写、§7 TDD 合流）。

### 3.3 概念级 C++ 示例语义不自洽

- **现象**：`DateRange::make` 按值返回，却号称「享元/始终返回同一对象」——自相矛盾。
- **根因**：写示例时只顾「像那么回事」，没验证语义。
- **修复**：贴合故事本质——**只有「空区间」是享元单例**（`emptyRange()` 返 `const&`），非空区间本就是不同的值、照常按值构造。

### 3.4 概念示例引入过多机制反而更乱

- **现象**：为让 `make` 返回引用，引入 `thread_local std::vector` 缓存池，偏离主旨。
- **根因**：为修一个小语义问题过度设计。
- **修复**：概念级示例应**最小化**，只演示要点（享元用于空区间），不引入无关生命周期管理。

### 3.5 笔记把跨节内容错放

- **现象**：「重构应永远由经济利益驱动 / 别用道德论证」放进了 §4.4（对经理说）。
- **根因**：该论点实际出自 2.5「延缓新功能开发」节。
- **修复**：移到对应节（§5.1），原处只留一句交叉引用。
