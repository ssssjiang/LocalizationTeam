## 2. 相机姿态估计（多视角，10 帧输入）

### 2.1 通用室内/室外场景（RealEstate10K / CO3Dv2）

测试协议：每场景随机选 10 张图；AUC@30 = 「旋转误差+平移误差都在 30° 以内的比例曲线下面积」（越高越好）。

```
RealEstate10K（未出现在任何方法的训练集）：

  COLMAP+SPSG      45.2     ~15s
  PixSfM           49.4     >20s
  DUSt3R           67.7     ~7s
  MASt3R           76.4     ~9s
  VGGSfM v2        78.9     ~10s
  ─────────────────────────────
  VGGT 前馈        85.3     ~0.2s  ← 纯前馈，快 50× 且更准
  VGGT + BA        93.5     ~1.8s  ← 加 BA 后更高

CO3Dv2：
  VGGT 前馈        88.2     ~0.2s
  VGGT + BA        91.8     ~1.8s
  VGGSfM v2        83.4     ~10s
```

关键数字：VGGT 前馈单项比 MASt3R（需要全局对齐的后优化）高 **8.9 个点（AUC@30，RealEstate10K）**，速度快 **35×**。

### 2.2 旅游地标场景（IMC 图像匹配挑战赛）

IMC 是 SfM 领域的高难度基准，以往由 COLMAP 风格的增量 SfM 主导。

```
方法                   AUC@3°   AUC@10°   时间
COLMAP (SIFT)           23.58    44.79     >10s
PixSfM (SP+SG)          45.19    70.47     >20s
VGGSfM                  45.23    73.92     ~6s
VGGSfMv2                59.32    76.82     ~10s
─────────────────────────────────────────────
VGGT 前馈               39.23    71.26     0.2s   ← AUC@10 已追上 VGGSfM
VGGT + BA               66.37    84.91     1.8s   ← 比 VGGSfMv2 高 8.1 个点
```

> VGGT + BA 达到 AUC@10° = **84.91**，在 CVPR'24 IMC 挑战赛相机姿态轨道上超过当时第一名 VGGSfMv2（76.82）[VGGT §C]。

## 3. 点云估计（稠密 3D 点）

### 3.1 ETH3D 基准（Chamfer 距离，越低越好）

```
方法                  精度↓    完整性↓   总体↓     时间
DUSt3R（全局对齐）    1.167    0.842     1.005     ~7s
MASt3R（全局对齐）    0.968    0.684     0.826     ~9s
─────────────────────────────────────────────────────
VGGT（点图头）        0.901    0.518     0.709     ~0.2s
VGGT（深度+相机）     0.873    0.482     0.677     ~0.2s  ← 更优（见后文）
```

VGGT 的「深度+相机反推点图」比「专用点图头」**更准（0.677 vs 0.709）**，原因见第 05 课「反直觉 trick」一节。

### 3.2 DTU 基准（Multi-View Stereo，无 GT 相机，越低越好）

```
方法（不知道 GT 相机）   精度↓    完整性↓   总体↓
DUSt3R                  2.677    0.805     1.741
VGGT（不知道 GT 相机）  0.389    0.374     0.382   ← 追上大部分知道 GT 相机的方法
```

知道 GT 相机的方法中，GeoMVSNet 最好（0.295），VGGT（0.382）在**不给相机先验**的条件下非常接近这个上限 [VGGT §4.2 Table 2]。

## 6. VGGT-Ω 的改进幅度

VGGT-Ω 在 VGGT 的基础上大幅提升，尤其在动态场景。

### 6.1 静态场景（VGGT-Ω 1B vs VGGT，AUC@30° / AbsRel 深度）

从 VGGT-Ω §Table 1、§Table 2 抽出典型数字（越高越好 / 越低越好）：

```
方法         7Scenes AUC@30°  ETH3D AUC@30°  NRGBD AUC@30°
VGGT           95.2            99.1            97.4
Ours-1B        98.4            99.6            99.8
Ours-10B       98.7            99.7            99.8
```

静态场景已经打到天花板附近，继续提升有限。

### 6.2 动态场景（Sintel）：77% 提升

Sintel 是光流/深度估计经典动态基准（包含复杂运动）：

```
MegaSaM（优化方法）   AUC@3°=22.5, AUC@30°=58.3, δ1.25=74.1   速度 ~50×慢
Depth Anything 3       AUC@3°=?,    δ1.25=74.1
VGGT                   AUC@3°=?,    AUC@30°=79.2
VGGT-Ω 1B              AUC@3°=?,    AUC@30°=89.5
VGGT-Ω 10B             AUC@3°=40.0, AUC@30°=93.5, δ1.25=93.5
```

VGGT-Ω 10B 在 Sintel 上的 AUC@3° = **40.0**，比此前最好的 22.5（MegaSaM）提升 **77%**；深度 δ1.25 = **93.5** vs 74.1，提升 **26%**；且比 MegaSaM **快 50×** [VGGT-Ω §1 Abstract、§4.2]。

### 6.3 缩放规律：幂律关系

VGGT-Ω 展示出明确的 scaling law [§4.3 Fig. 1]：

- **模型参数** 0.2B → 10B：point error 0.107 → 0.046（6 个基准平均）
- **训练数据** 2K → 2M 序列：point error 0.275 → 0.073

两条曲线都近似**幂律（power law）**关系，和 LLM scaling 表现类似，说明 feed-forward 3D 重建也服从 scale-up 的规律。

### 6.4 推理速度（VGGT-Ω vs VGGT vs DA3-Giant，A100 80GB）

- VGGT-Ω 和修正后的 VGGT 均可在单张 A100 处理超过 **1250 帧**（DA3-Giant 约 750 帧 OOM）。
- VGGT-Ω 因 DINOv3 patch size 16（vs DINO v2 patch size 14）token 数减少约 25%，速度比 VGGT 快 **20–25%**。
- 极速变体（全部全局 attention 替换为 register attention）：1000 帧仅需 **11.7s**（vs 原始 240.2s），但精度有所下降 [VGGT-Ω §4.2]。

## 7. 数字背后的限制（不可忽视）

以上数字均在**标准基准、每场景 10 帧**协议下测得。以下条件下精度会下降，原文明确指出 [VGGT §5]：

- **鱼眼 / 全景相机**：VGGT 不支持，精度未知。
- **极端旋转（大基线）**：重建质量明显下降。
- **大规模序列（数百~数千帧）**：训练时每场景最多采 24 帧，长序列性能未经过系统评估。
- **强烈非刚性形变**（如人体快速舞动）：VGGT 会失败；VGGT-Ω 部分改善但未完全解决。
