# 📘 补充 04：VGGT 能否取代 COLMAP？——有条件能，有条件不行

> 真实来源（全部 confirmed）：
> - **VGGT** [arXiv 2503.11651] §1、§4.1–§4.3、§5、Table 1/2/3/9/10
> - **VGGT-Ω** [arXiv 2605.15195] §1、§3.5.2、§4.2、Fig. 7

---

## 1. 速查结论（先看这里）

| 条件 | VGGT 能否替代 COLMAP | 依据 |
|---|---|---|
| 几十帧、普通相机、精度优先 | **能，且更准更快** | AUC@10° 84.91 vs 44.79；速度快 5-50×  |
| 需要极快速度，精度次之 | **能，纯前馈 0.2s** | VGGT 前馈 AUC@10° 71.26 vs 44.79 |
| 鱼眼 / 全景相机 | **不行** | VGGT 不支持，无 benchmark |
| 极端大基线（极端旋转） | **不行** | 精度明显下降，原文明确 [VGGT §5] |
| 城市级（数千~百万帧） | **目前不行** | 训练最多 24 帧/场景；架构二次复杂度 |
| 强烈非刚性（动态场景） | **VGGT 不行，VGGT-Ω 部分可以** | VGGT §5；VGGT-Ω §1 |
| 需要可审计/可解释 | **不行** | VGGT 是黑盒，COLMAP 全程可溯源 |
| 无 GPU 环境 | **不行** | VGGT 依赖 GPU 推理 |

---

## 2. 「能」的数据依据

### 2.1 标准相机姿态精度已全面超越

最直接的比较来自 VGGT 论文 §4.1 Table 1 和 §C Table 10（H100 测试）：

**RealEstate10K（10 帧/场景，AUC@30，越高越好）：**

```
COLMAP + SPSG    45.2     ~15s
VGGT 前馈        85.3     ~0.2s   ← +88% relative，快 75×
VGGT + BA        93.5     ~1.8s   ← +107% relative，快 8×
```

**IMC 旅游地标（AUC@10°，越高越好）：**

```
COLMAP (SIFT)    44.79    >10s
VGGT 前馈        71.26    0.2s    ← +59%，快 50×+
VGGT + BA        84.91    1.8s    ← +90%，且 VGGT+BA 比 VGGSfMv2(76.82) 更高
```

无论是精度还是速度，在这两个基准上 VGGT（+BA）全面领先 COLMAP。

### 2.2 COLMAP 在 VGGT-Ω 的数据标注管线里仍被用作「后端」

这是一个容易忽视的细节：VGGT-Ω 在构建大规模训练数据时，**用 VGGT 初始化相机 → 再跑 COLMAP 做 Bundle Adjustment + 过滤** [VGGT-Ω §3.5.2]。这说明：

- 在数据标注这个「高精度、离线处理」场景里，VGGT+COLMAP 组合比单独 COLMAP 更可靠（VGGT 提供更好的初始值，降低 COLMAP BA 失败率）；
- 同时也说明 COLMAP 在高精度 BA 精炼这个环节依然有其价值——**两者更像「互补」而非「替代」**。

## 3. 「不行」的数据依据与结构性原因

### 3.1 大规模场景：架构有原生上限

VGGT 的全局 self-attention 复杂度是 $O(N^2 \cdot K^2)$（$N$=帧数，$K$=每帧 token 数）。实测 [VGGT §5 Table 9]：

```
200 帧 → 8.75s，40.63 GB（H100）
```

VGGT-Ω 在修正后最多支持单 A100（80GB）处理约 **1250 帧** [VGGT-Ω §4.2 Fig. 7]。

COLMAP 的增量 SfM 可以处理**数万到数十万张**图（「Building Rome in a Day」是 150 万张），VGGT 在这个量级完全无法直接使用。

**结论**：VGGT 适用于**每场景几十到约 100–200 帧**的重建任务；城市级或建图级别的大规模场景，当前架构直接不适用。

### 3.2 鱼眼/全景/极端旋转：训练分布限制

VGGT-Ω 的数据标注管线明确过滤掉了视场角在 [30°, 120°] 范围之外的序列 [VGGT-Ω §3.5.2]。加上 VGGT 原文 §5 明确指出「不支持鱼眼、全景；极端旋转下精度下降」。

COLMAP 本身不限定相机模型，可以用鱼眼模型（OpenCV distortion、Kannala-Brandt 等）。

**结论**：在这些相机类型上，COLMAP 仍是首选。

### 3.3 强烈非刚性：VGGT 的假设被违反

VGGT 假设场景是**静态或接近静态**的（点图、深度图都是单时刻的几何描述）。原文 §5：「在非刚性形变强烈的场景下会失败」。

VGGT-Ω 通过动态场景训练数据和深度+相机参数的独立解耦，部分改善了动态场景的处理，但极速运动或强形变场景仍是挑战 [VGGT-Ω §3.3]。

**结论**：无人机+大运动+人群场景，COLMAP 的 RANSAC+三角化框架加上动态点过滤（e.g. 用分割模型去掉动态物体）仍然比 VGGT 更可控。

### 3.4 「可解释性/可审计」需求

COLMAP 的每个步骤（特征提取 → RANSAC → 三角化 → BA）都完全透明：失败在哪步、哪个图配准失败、哪条轨迹被滤掉，全程可查。

VGGT 是端到端神经网络，一次前馈出结果，内部推理过程不透明。如果需要**生产级可靠性审计**（如自动驾驶定图、测量级三维测量），这是硬限制。

### 3.5 无 GPU 环境

VGGT 1.2B 参数需要 GPU 推理（1 帧 0.04s / 1.88GB VRAM，H100）；COLMAP 可以纯 CPU 运行（慢但可用）。

## 4. 最清晰的条件表述

```
在以下条件下，VGGT（+BA）可以替代 COLMAP：
  ✅ 普通透视相机（非鱼眼/全景）
  ✅ 每场景 2–200 帧（VGGT），或 ~1000 帧（VGGT-Ω，单 A100）
  ✅ 静态场景，或轻微动态（VGGT-Ω 支持更多动态）
  ✅ 有 GPU 可用（运行 VGGT 本身）
  ✅ 不需要可审计/透明推理

在以下条件下，COLMAP 仍然不可替代（或 VGGT 无法直接使用）：
  ❌ 鱼眼、全景、大畸变相机
  ❌ 极端大旋转基线
  ❌ 数千帧以上大规模建图
  ❌ 强烈非刚性形变（VGGT）；中等动态（VGGT-Ω 已部分支持）
  ❌ 无 GPU 环境
  ❌ 需要完全透明、逐步可审计的 SfM 流程
```

---

## 5. 更合理的定位：互补而非替代

两篇论文的实验本身给出了这个定位——**VGGT 的最佳用法是和 BA 结合，而不是替代 BA**：

- VGGT 前馈出接近准确的相机位姿 + 稠密点云，作为 BA 的高质量初始值；
- BA（可以是 COLMAP 里的，也可以是其他实现）在此基础上做精炼，**跳过传统 BA 里最贵的「三角化+初始化」阶段**；
- 结果：VGGT+BA 在 1.8s 内达到 AUC@10° = 84.91，而传统 COLMAP 需要 >10s 且精度只有 44.79。

VGGT-Ω 的数据标注管线也是这样做的：VGGT 初始化 → COLMAP BA + 过滤 [VGGT-Ω §3.5.2]。

> 🎯 一句话定位：**VGGT 是 SfM 的前端革命（把相机估计从「多步迭代」变成「一次前馈」），COLMAP 依然在后端 BA 精炼和大规模建图场景里有不可替代的位置。**
