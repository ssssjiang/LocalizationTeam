# 📘 第 05 课：VGGT 架构——alternating attention + 多预测头 + 那个反直觉的推理 trick

> 真实来源：**VGGT** [arXiv 2503.11651](https://arxiv.org/abs/2503.11651)，本课引用 **§3.2 Feature Backbone、§3.3 Prediction heads、§3.4 Training、Fig. 2、Table 3**。
> 学习目标：把第 04 课「一次前馈出全套 3D 属性」拆开看内部——token 怎么进、attention 怎么交替、几个头怎么各管一摊，最后**正面兑现第 04 课 Q3 的伏笔**：为什么「深度+相机反推点图」比「专用点图头」更准（带 ETH3D 实测数字）。

---

## 开场：把第 04 课的黑盒打开

第 04 课你已经知道 VGGT 是个函数：

$$
f\bigl((I_i)_{i=1}^N\bigr) = (g_i,\, D_i,\, P_i,\, T_i)_{i=1}^N
$$

今天把这个 $f$ 拆成一条流水线（§Fig. 2）：

```
N 张图
  │  ① DINO 切 patch → 每帧一堆 image token
  │  ② 每帧再加：1 个 camera token + 4 个 register token
  ▼
③ Alternating-Attention 主干（L=24 层：帧内注意力 / 全局注意力 交替，无 cross-attention）
  │
  ├─④ Camera Head  ← 吃 camera token  → 相机参数 g
  └─④ DPT Head     ← 吃 image token   → 深度图 D / 点图 P / 跟踪特征 T
                                          └─⑤ Tracking Head（CoTracker2）→ 2D 轨迹
```

> 🎯 一句话：**整个网络只有 self-attention（无 cross-attention），靠「帧内 / 全局」两种注意力交替，把跨图信息融合塞进网络内部；输出端挂几个轻量头，各取所需。**

---

## 一、输入端：DINO 切 token + 两种特殊 token

### 1.1 image token：DINO 把每张图切成块

每张输入图 $I$ 先被 **DINO**（第 01 课讲过的自监督 ViT backbone）切成 $K$ 个 patch token，$t^I \in \mathbb{R}^{K\times C}$。$K$ 取决于分辨率。

> 🎯 这一步就是第 01 课「DINOv2 当 backbone」的兑现——VGGT 不从像素硬学，而是站在 DINO 的几何感知特征上起步。

### 1.2 camera token + register token：每帧多塞 5 个

除了 image token，每帧还额外拼上（§3.3）：

- **1 个 camera token** $t^g_i \in \mathbb{R}^{1\times C'}$：专门负责"凝聚这一帧的相机信息"，最后交给 camera head。
- **4 个 register token** $t^R_i \in \mathbb{R}^{4\times C'}$：第 01 课讲过的 ViT register（[2309.16588](https://arxiv.org/abs/2309.16588)），给网络一块"草稿纸"放全局/中间计算，让 patch 特征更干净。

所以每帧进 transformer 的是 $(t^I_i,\ t^g_i,\ t^R_i)$ 拼起来，所有帧并在一起送进主干。

> 💡 **register token 用完即扔**：输出端 $\hat{t}^R_i$ 直接丢弃，只有 $\hat{t}^I_i$（→稠密预测）和 $\hat{t}^g_i$（→相机）参与最终预测。register 的价值在「算的过程中」，不在「算的结果里」。

### 1.3 第一帧用「不一样的」camera/register token

这是 VGGT 安放「第一台相机=世界系」这个约定的精巧之处：

> 📖 §3.3：第一帧的 camera/register token $(\bar{t}^g, \bar{t}^R)$ 是**一套单独的可学习 token**，和其余所有帧共用的那套 $(t^g, t^R)$ **不同**。

为什么这么设计？

- 这样网络能**从 token 层面分辨「谁是第一帧」**，进而把所有 3D 预测摆进**第一台相机的坐标系**（继承自 DUSt3R，第 03 课）。
- 配套地（§3.3 Coordinate Frame）：第一台相机的外参被**钉死为单位变换**——旋转四元数 $q_1=[0,0,0,1]$、平移 $t_1=[0,0,0]$。其它帧的位姿都相对它表达。

> 🎯 回收第 03 课的「神之一手」：DUSt3R 用「把第二张图的点也吐在第一张图坐标系里」消掉了配准；VGGT 把这个约定**内建进 token 设计**——第一帧一套特殊 token，天然就是世界原点。

## 二、主干：Alternating-Attention（这是唯一的「3D 特殊照顾」）

第 04 课说 VGGT「几乎没有 3D 归纳偏置」，**唯一的例外**就是这里。

### 2.1 两种注意力交替

标准 Transformer 是「一视同仁的全局 self-attention」。VGGT 改成两种交替（§3.2）：

| 注意力类型 | 注意范围 | 作用 |
|---|---|---|
| **帧内 self-attention** | 只在**同一帧内部**的 token 之间 | 整理单张图自己的结构；归一化本帧激活值 |
| **全局 self-attention** | 跨**所有帧**的全部 token | 把不同图之间的信息打通、对齐 |

默认 **L=24 层**帧内 + 24 层全局，交替堆叠。**全程没有任何 cross-attention，只有 self-attention。**

> 📖 §3.2 原话（意译）：交替帧内/全局，是在「跨图整合信息」和「逐图归一化激活」之间取平衡。

### 2.2 为什么不直接用「全程全局注意力」？

- 全程全局：所有帧所有 token 一锅炖，计算量随「总 token 数」平方爆炸，且单帧内部的结构信息容易被淹没。
- 全程帧内：每帧自己玩，**跨图信息永远融不到一起**——那就退回 DUSt3R 的「成对」困境了。
- **交替**：帧内层负责"把每张图自己看懂"，全局层负责"把几百张图的信息对齐"，两者轮流，既省算力又能融合。

> 🎯 这就是第 04 课「断点一：一次吃几百张图」的实现机制——**跨图融合靠的是网络内部的全局 attention 层，不是网络外面的优化拼接**。CoTracker 的「联合跟踪」、DUSt3R 的「成对融合」，到这里被统一成「一个 transformer 里交替的两种 attention」。

### 2.3 顺序不敏感（除了第一帧）

主干对输入帧的顺序是 **permutation equivariant**（除第一帧外，换顺序不影响结果）。所以 VGGT 不假设时间顺序，**视频、乱序图集都能喂**——和第 02 课 VGGSfM 的 tracker 一样不依赖时序。

## 三、输出端：三个头，各管一摊

主干输出 refined token 后，挂三个头（§3.3）。

### 3.1 Camera Head：从 camera token 出相机参数

- 输入：每帧的输出 camera token $\hat{t}^g_i$。
- 结构：**4 层额外 self-attention + 1 个 linear 层**。
- 输出：相机参数 $\hat{g}_i \in \mathbb{R}^9 = [$四元数 $q$, 平移 $t$, 视场角 $f]$（内参+外参）。

### 3.2 DPT Head：从 image token 出所有稠密量

- 输入：每帧的输出 image token $\hat{t}^I_i$。
- 结构：**DPT 层**（[2103.13413](https://arxiv.org/abs/2103.13413)，把 transformer token 重组成稠密特征图）→ 得到稠密特征 $F_i \in \mathbb{R}^{C''\times H\times W}$ → 再用 **3×3 卷积**映射出：
  - 深度图 $D_i$
  - 点图 $P_i$
  - 跟踪特征 $T_i$（喂给 tracking head）
- 额外还出 **aleatoric uncertainty**（不确定度）图 $\Sigma^D_i$、$\Sigma^P_i$：训练时进损失加权，训练完后正比于「模型对该预测的置信度」。

> 💡 注意：**深度、点图、跟踪特征共享同一个 DPT head 的特征 $F_i$**，只是最后用不同的卷积/分支分出去。这呼应第 04 课「多任务共享 backbone 反而更准」——它们连预测头的大部分都共享。

### 3.2.1 【补充】稠密特征 vs 传统「特征点」：VGGT 跳过了哪步？

这里有一个容易混淆的概念值得单独说清楚（confirmed，§3.1/§3.3）。

**传统 SfM 五步（第 00 课）的第一步是「检测关键点（keypoint detection）」**——用 SIFT / SuperPoint 等检测器，主动挑出图中「值得追的稀疏显著点」（角点、斑点等），每张图几百到几千个稀疏点。

**VGGT 整步砍掉了这个检测步骤。** 它不"先挑哪些点是好特征"，而是 DPT head 对所有像素一视同仁地输出**稠密跟踪特征图** $T_i \in \mathbb{R}^{C \times H \times W}$——**每个像素都有一个 $C$ 维特征向量**，没有任何稀疏筛选。

| | 传统 keypoint detection | VGGT 的 dense feature |
|---|---|---|
| **稀疏 vs 稠密** | 稀疏（每图几百~几千个点） | **稠密**（每像素一个特征向量） |
| **谁决定追哪个点** | **模型**（检测器选出显著点） | **你**（给任意 query 点，模型追） |
| **用途** | 直接参与匹配/特征描述 | 喂给 tracking head，再算 2D 坐标 |

结果是：**你可以给 VGGT 任意一个像素位置作为 query 点**，它都能在稠密特征图上采样到对应特征，然后算出这个点在其他帧的位置。这和"挑稀疏关键点再跟踪"是两套完全不同的逻辑。

> 🎯 这正是 VGGT「没有 keypoint detection 头」的原因——不是漏掉了，而是**设计上就不需要**。传统 SfM 里「检测→描述→匹配」三步，到 VGGT 这里被「稠密特征图 + CoTracker2 式相关匹配」一步替代。

### 3.3 Tracking Head：CoTracker2 算 2D 轨迹

- 用 **CoTracker2 架构**（第 01 课讲过的联合点跟踪，[2307.07635](https://arxiv.org/abs/2307.07635)）。
- 流程：给定 query 图上一个点 $y_j$ → 在 query 的特征图上**双线性采样**取它的特征 → 和其它所有帧的特征图做**相关（correlation）** → 得到一堆 correlation map → 过 self-attention → 出所有帧里对应的 2D 点 $\hat{y}_i$。
- 同样**不假设时序**，任意图集都能用。

> 🎯 第 04 课说「VGGT 不直接输出 track，而是输出跟踪特征 $T$」——原因就在这：主干只负责产出**稠密跟踪特征**，真正算轨迹的是这个独立的 CoTracker2 头，两者端到端联合训练。

## 四、训练：一个多任务损失 + 几个工程关键点

### 4.1 多任务损失（§3.4 Eq. 2）

$$
\mathcal{L} = \mathcal{L}_{\text{camera}} + \mathcal{L}_{\text{depth}} + \mathcal{L}_{\text{pmap}} + \lambda\,\mathcal{L}_{\text{track}}
$$

- $\mathcal{L}_{\text{camera}}$：预测相机 vs GT，用 **Huber loss**。
- $\mathcal{L}_{\text{depth}}$ / $\mathcal{L}_{\text{pmap}}$：跟 DUSt3R 一样的**不确定度加权损失**（用预测的 $\Sigma$ 加权误差），并额外加 **梯度项**（$\nabla\hat{D}$ vs $\nabla D$，单目深度常用，让边缘更锐）。
- $\mathcal{L}_{\text{track}}$：预测 2D 点 vs GT 对应点的距离 + 可见性 BCE 损失。
- 相机/深度/点图三项量级相近，**不用互相加权**；只有 track 项下调到 $\lambda=0.05$。

### 4.2 坐标归一化：但「不」加在网络输出上（关键细节）

3D 重建有个固有歧义：**整体缩放或换参考系，图像完全不变**，所以重建结果差一个相似变换都"合法"。VGGT 消歧的做法（§3.4）：

1. 所有量先表达在第一台相机系里；
2. 算点图里所有 3D 点到原点的**平均欧氏距离**，用它把平移 $t$、点图 $P$、深度 $D$ 统一归一化。

> 🎯 **和 DUSt3R 的关键区别**：DUSt3R 会对网络输出也做归一化；VGGT **不对输出做归一化**，而是**强迫网络自己从训练数据里学会这个归一化**。换句话说——别让后处理替网络"摆正尺度"，让网络自己学会直接吐出摆正的结果。这正是 VGGT「把活干在网络内部」哲学的又一处体现。

### 4.3 规模（§3.4 Implementation）

- **约 1.2B 参数**，L=24 层交替注意力。
- **64 张 A100 训 9 天**，160K 迭代，AdamW，峰值 lr 2e-4。
- 每个 batch 从一个场景随机采 **2–24 帧**；图缩到最长边 518px，宽高比随机。
- 训练数据：Co3Dv2 / BlendMVS / DL3DV / MegaDepth / ScanNet / HyperSim / Kubric …十几个数据集，室内外、合成+真实都有，规模与 MASt3R 训练集相当。

> 💡 这就是第 04 课「凭什么敢拔掉 BA 还更准」的物质基础：**1.2B 参数 + 十几个 3D 标注数据集 + 64×A100×9 天**。前馈精度是"砸数据和算力砸出来的"，不是靠几何先验。

## 五、兑现伏笔：为什么「深度+相机」推的点图，比「点图头」直接出的准？

第 04 课 Q3 的钩子，现在正面回答。

### 5.1 over-complete：明明能互推，为什么各预测各的？

相机 $g$、深度 $D$、点图 $P$ 之间有闭式关系（$g$ 可从 $P$ 解 PnP；$D$ 可从 $P+g$ 推）。VGGT 却让网络**每样都单独预测**（over-complete，过完备）。

> 📖 §3.1 / §4.5：训练时**显式预测所有量**（哪怕冗余）能带来**明显精度提升**——多个相关任务互相当正则，逼着共享特征学得更扎实。

### 5.2 推理时的反直觉发现：点图头反而不如「深度+相机」

更有意思的是推理阶段（§4.5 / Table 3，ETH3D 点图重建）：

| 方法 | Acc↓ | Comp↓ | Overall↓ | 耗时 |
|---|---|---|---|---|
| DUSt3R（含 global alignment） | — | — | 较差 | ~9s |
| MASt3R（含 global alignment） | 0.968 | 0.684 | 0.826 | ~9s |
| **VGGT（Point head 直接出点图）** | 0.901 | 0.518 | 0.709 | **~0.2s** |
| **VGGT（Depth + Cam 反推点图）** | **0.873** | **0.482** | **0.677** | **~0.2s** |

（指标越低越好。）两个结论：

1. **VGGT 前馈（0.2s）已经全面超过 DUSt3R/MASt3R（带 9s 全局优化）**——第 04 课「断点二」的硬证据。
2. **「深度图头 + 相机头」反投影出来的点图（0.677），比「专用点图头」直接出的（0.709）更准。**

### 5.3 为什么会这样？（直觉）

> 🎯 直接回归 3D 点图，等于让网络对每个像素**直接吐一个 3D 坐标 $(x,y,z)$**——这是个"全局、绝对"的量，跨图、跨尺度都要对齐，很难学。
>
> 而拆成「**深度**（每像素 1 个标量，局部、规整、和图像纹理强相关）+ **相机**（每帧一个 9 维全局位姿）」两个**对网络更友好**的子问题，分别学好，再用几何公式 $P = \text{unproject}(D, g)$ 反投影合成点图——精度反而更高。

> 💡 这就是 VGGT-Ω（第 06 课）后来**干脆精简掉独立点图头、只留一个 dense head** 的伏笔：既然点图本来就该从 深度+相机 合成，那专门养一个点图头就是冗余。

### 5.4 BA 仍可选叠加（回收第 04 课）

> 📖 §4：用 BA 进一步 refine 预测的相机位姿和 track，能再涨精度。VGGT 直接预测的近似准确的点/深度图，正好**给 BA 当极好的初值**。

> 🎯 精确口径（再次强调）：**VGGT 不需要 BA；但 VGGT 的前馈结果是 BA 的绝佳初值，想叠加 BA 还能再涨**。后优化从"必需品"变"可选增益"。

## 六、一句话总结今天

> 🎓 **VGGT = DINO 切 token →（每帧 +1 camera token +4 register token，第一帧用特殊 token 锁定世界系）→ 24 层「帧内/全局」交替的纯 self-attention 主干 →（camera head 出相机 / DPT head 出深度·点图·跟踪特征 / CoTracker2 head 出轨迹）。1.2B 参数砸十几个数据集训出前馈精度，跨图融合全在网络内部的全局 attention 里完成。最反直觉的一招：让网络过完备地各预测各的，推理时用「深度+相机」反投影点图（0.677）反而比专用点图头（0.709）更准——这也是 VGGT-Ω 砍掉点图头的伏笔。**
