# 📘 第 06 课：VGGT-Ω——register attention + 单 dense head，怎么把这套 scale 上去

> 真实来源：**VGGT-Ω** [arXiv 2605.15195](https://arxiv.org/abs/2605.15195)（Wang, Chen, Zhang, Karaev, Schönberger, Labatut, Bojanowski, Novotny, Vedaldi, Rupprecht；Oxford VGG + Meta AI；**CVPR 2026 Oral**，2026-05-14 提交）/ 项目页 [vggt-omega.github.io](https://vggt-omega.github.io/)。本课依据其 **Abstract + 项目页 Key Takeaways**（论文正文 HTML 截至写课时未在 arXiv 放出，故机制细节只讲来源明确支撑的部分，推测性内容会显式标注）。
> 学习目标：搞清 VGGT 已经那么强了，VGGT-Ω 还在解决什么问题（答案：**scaling**），以及它靠哪几处架构改动把显存压到 VGGT 的 ~30%，从而能用 15× 的数据训。顺带**兑现第 05 课「砍掉点图头」的伏笔**。

---

## 开场：VGGT 已经赢了 Best Paper，为什么还要 Ω？

第 04、05 课我们看到 VGGT 很强：前馈、几百张图、不要 BA、还更准。那 VGGT-Ω 改什么？

> 📖 Abstract 开宗明义：像 VGGT 这类前馈重建模型，质量**随模型规模和数据规模可预测地提升（scales predictably）**。

这句话是整篇的"题眼"：

- 既然「越大越好」是条**可预测的规律**（类似 LLM 的 scaling law），那自然的下一步就是——**把它做大**：更多数据、更多帧、更难的场景（动态）。
- 但 VGGT 那套架构（24 层全局注意力 + 1.2B 参数）**太吃显存，scale 不上去**。

> 🎯 所以 VGGT-Ω 的主线**不是**"换个更聪明的几何思路"（那是第 02→04 课干的事），而是**"工程上把这套架构改得能 scale"**。一句话：**VGGT 解决了「能不能前馈出 3D」，VGGT-Ω 解决「怎么把它 scale 到更大数据 / 更多帧 / 动态场景」。**

---

## 一、瓶颈在哪：全局注意力的显存账

要理解 Ω 的改动，先看 VGGT 卡在哪。

回忆第 05 课：VGGT 主干是 **24 层「帧内 / 全局」交替的 self-attention**。问题出在**全局注意力**：

- 全局层要让**所有帧的所有 token 两两互相注意**。
- token 总数 ≈ 帧数 × 每帧 patch 数。帧越多、分辨率越高，token 越多，**注意力计算和显存随 token 数平方增长**。
- 再叠上第 05 课的 DPT head 里那些**高分辨率卷积层**，稠密预测也很吃显存。

> 🎯 结果：VGGT 训练时显存吃紧，**喂不进更多数据 / 更长序列 / 动态场景**。Ω 的几处改动，全是冲着「把这两块显存大头压下来」去的。

---

## 二、四处架构改动（按「省显存」这条主线串起来）

> 📖 Abstract 原文列了四点改动。下面按「它们各自省了哪块显存」来组织（归纳到同一个目标：训练效率）。

### 2.1 单个 dense 预测头（多任务共享）—— 兑现第 05 课伏笔

> 📖 Abstract：用**单个 dense prediction head + 多任务监督**简化 VGGT 的架构。
> 📖 项目页 Key Takeaway：**「相机参数 + 深度图，就是足够且紧凑的重建目标（sufficient and compact targets）」**。

这正是第 05 课 §5 埋的钩子：

- 第 05 课实测：VGGT 里「**深度+相机** 反推点图」(0.677) 比「专用**点图头**」(0.709) 还准——说明点图头本就**冗余**。
- VGGT-Ω 顺势**砍掉独立点图头**：既然点图本该从 深度+相机 合成，就别单独养一个头。只保留预测**相机参数 + 深度图**这两个"足够且紧凑"的目标，点图按几何公式 unproject 出来。
- 多个稠密量（深度等）**共用一个 dense head**，用多任务监督一起学。

> 💡 第 05 课"反直觉的发现"，到这里变成了"架构上的精简决策"——这就是为什么我在第 04、05 课反复埋这个伏笔：它是贯穿 VGGT→Ω 的一条主逻辑线。

### 2.2 去掉昂贵的高分辨率卷积层

> 📖 Abstract：**移除昂贵的高分辨率卷积层（high-resolution convolutional layers）**。
> 📖 项目页致谢：感谢 Tianhong Li 关于「dense decoding head 应当**只用 MLP**」的讨论（参见 JiT）。

- 第 05 课的 DPT head 末端有 3×3 卷积等高分辨率操作，显存/算力开销大。
- Ω 把稠密解码头改成**更轻的（MLP 为主）结构**，省掉高分辨率卷积这块大头。

> 🎯 这一条和 2.1 是一对：**2.1 砍掉一个头（点图头），2.2 把剩下的头做轻（去高分辨率卷积）**。稠密预测端整体瘦身。

### 2.3 用 register 把全局信息「压」成紧凑表示

> 📖 Abstract：用 **registers 把场景信息聚合成一个紧凑表示（compact representation）**。
> 📖 项目页 Key Takeaway：**「register 是全局信息的天然载体」**。

回忆第 05 课：VGGT 每帧带 4 个 register token，但当时它们更多是"草稿纸"、用完即扔。VGGT-Ω 给 register **升级了角色**：

- 让 register **主动聚合整个场景的全局信息**，成为场景的紧凑摘要。
- 这是下一条（register attention）的前提——既然全局信息被 register 收拢了，跨帧交流就可以只走 register。

### 2.4 register attention：跨帧只通过 register 交流

> 📖 Abstract：引入 **register attention**——把**跨帧的信息交换限制到这些 register 上，部分替代全局注意力**。
> 📖 项目页 Key Takeaway：**「register attention 让（全局信息的）交换变得高效」**。

这是 Ω 最核心的一刀，直接砍掉 §1 那笔"全局注意力平方显存账"：

- **VGGT（旧）**：全局层 = 所有帧所有 token 两两注意 → 随 token 数平方爆炸。
- **VGGT-Ω（新）**：跨帧信息**不再让所有 token 互相注意**，而是**只通过少量 register 中转**——每帧把信息汇到自己的 register，register 之间（少量 token）再交流，然后分发回各帧。
- register 数量远小于 patch token 数，所以**跨帧交流的代价从「token 数平方」降到「register 数 × token 数」量级**（这是基于"限制到 register"的直觉推断 —— *unverified mechanism detail*；论文正文未取到，确切实现以原文为准）。

> 🎯 类比：原来是「全班同学每人都要和其他所有人单独对一遍话」（平方）；现在是「每组选一个组长（register），信息先汇给组长，组长之间开个小会，再传达回组内」。**用「组长中转」替代「全员互联」**，这就是 register attention 省显存的核心思路。

---

## 三、payoff：显存降到 ~30%，数据涨到 15×

四处改动叠起来，效果非常直接：

> 📖 Abstract：训练时 VGGT-Ω **只用前代约 30% 的 GPU 显存**，因而能用**比此前工作多 15× 的有标注数据**训练，并能**利用海量无标注视频**。

这条因果链是全文的工程主轴：

```
架构瘦身（单 head + 去高分卷积 + register attention）
   → 显存降到 ~30%
   → 同样的卡能塞 15× 数据 + 海量无标注视频
   → scaling law 生效，重建质量随数据/模型规模提升
```

> 💡 注意这和第 05 课「VGGT 靠 1.2B 参数 + 64×A100×9 天 砸出前馈精度」是同一个逻辑的延续：**前馈重建是"数据和算力驱动"的，所以谁能更省显存、喂更多数据，谁就更强**。VGGT-Ω 的贡献本质是"把喂数据的天花板抬高"。

---

## 四、结果与外溢：从静态到动态，从重建到具身

### 4.1 静态 + 动态都更强

> 📖 Abstract：VGGT-Ω 在多个 benchmark 上对**静态和动态场景**都取得强结果；例如在 **Sintel 上把相机估计精度相对此前最好结果提升 77%**。

- VGGT 主要面向**静态场景**；VGGT-Ω 通过"支持动态场景的数据标注 pipeline + 自监督协议"（第 07 课细讲），把能力扩到**动态场景**。
- 这对你的工作很相关：现实采集（割草机、扫地机、手持）几乎都有动态物体，静态假设是传统 SfM 的硬伤。

### 4.2 register 还能喂给 VLA / 对齐语言

> 📖 Abstract + 项目页 Key Takeaway：学到的 register 能**改善 VLA（Vision-Language-Action）模型**，且**能和语言对齐**；这说明**「重建」可以当作空间理解的一个强大且可 scale 的代理任务（proxy task）**。

> 🎯 这是 Ω 一个很有野心的外溢论点：**用"学会重建 3D"作为预训练代理任务，学到的 register 表示自带空间理解能力，可以迁移去帮具身（VLA）和多模态对齐**。和你之前 AI talk 里「World Model / 具身」那条线能接上——重建不只是"建图工具"，可能是空间智能的基础表示。

---

## 五、一句话总结今天

> 🎓 **VGGT-Ω = 把 VGGT「scale 上去」的工程版本。核心是四处瘦身：① 砍掉点图头、只留「相机+深度」这对足够紧凑的目标（兑现第 05 课伏笔）；② dense head 改 MLP、去掉高分辨率卷积；③ 让 register 聚合全局信息成紧凑摘要；④ register attention——跨帧信息只走 register 中转、替代全员全局注意力，砍掉平方显存账。结果显存降到 ~30%，数据涨到 15×，静/动态场景都更强（Sintel 相机精度 +77%），学到的 register 还能反哺 VLA 和语言对齐。**
