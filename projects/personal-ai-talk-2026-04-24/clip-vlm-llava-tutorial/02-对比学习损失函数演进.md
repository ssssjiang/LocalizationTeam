## 一、问题陈述

世界观立住了：我们要让 anchor 与 positive 的表征近、与 negative 的表征远。**问题是这个 loss 怎么写？**

历史给出了三步演进，每一步都在修补前一棒的短板：

```
Triplet Loss (2015)
   │  短板：一次只看 1 个 negative
   ▼
N-pair Loss (2016)
   │  短板：负样本结构松散，需手工配对
   ▼
InfoNCE (2018)  ← 对比学习的"标准答案"，CLIP 直接继承
```

我们一棒一棒看。

---

## 二、第一棒：Triplet Loss（FaceNet, 2015）

### 数学形式

每次喂 3 张图：

- $a$：anchor（如某人 A 的一张照片）
- $p$：positive（同一个人 A 的另一张照片）
- $n$：negative（另一个人 B 的照片）

通过编码器得到表征 $f(a), f(p), f(n)$，然后定义损失：

$$
\mathcal{L}_{\text{triplet}} = \max\Big(0,\ \|f(a) - f(p)\|_2^2 - \|f(a) - f(n)\|_2^2 + \alpha\Big)
$$

### 拆解每一项

| 部分 | 含义 |
|---|---|
| $\|f(a) - f(p)\|_2^2$ | anchor 到 positive 的欧氏距离平方 |
| $\|f(a) - f(n)\|_2^2$ | anchor 到 negative 的欧氏距离平方 |
| $\alpha$ | margin（边界），通常取 0.2 |
| $\max(0, \cdot)$ | 像 hinge loss 一样，差距已经够大就不再优化（loss 为 0） |

### 它在做什么？

**用大白话翻译这个公式：**

> "anchor 到 positive 的距离，应当**至少**比 anchor 到 negative 的距离**少一个 margin α**。否则就有 loss，要继续训练。"

如果 $\|f(a) - f(n)\|^2 - \|f(a) - f(p)\|^2 \geq \alpha$ → loss = 0，已经够好了，跳过。

如果不够 → loss 是它们的差距，反传梯度推开 negative、拉近 positive。

### 经典应用：FaceNet（人脸识别）

FaceNet（Schroff et al., 2015）用 Triplet Loss 训出了一份人脸表征：**任意两张同一个人的照片在表征空间里距离 < 阈值；任意两张不同人的照片 > 阈值**。这套表征支撑了之后所有人脸识别系统的工业基础。

### 短板

> **一次训练只看 1 个 negative。**

这有什么问题？想象你在训练"猫"的表征：

- 这一步：anchor = 猫，negative = 狗 → 模型学到"猫不是狗"
- 下一步：anchor = 猫，negative = 树 → 模型学到"猫不是树"
- ……

但是"不是猫"的种类有**无穷多**——狗、树、车、桌子、海……每次只对比 1 个 negative，模型学到的"猫"边界**非常局部、非常脆弱**。

更要命的是工程层面：**每个 batch 必须手工挑出 (a, p, n) 三元组**。挑得不好（比如 negative 太容易区分），模型学不到东西。FaceNet 论文里花了大篇幅讲"hard negative mining"——在一个 batch 里如何挑出**难度合适**的 negative。这是个工程灾难。

→ **能不能一次比一群？**

## 三、第二棒：N-pair Loss（Sohn, 2016）

### 数学形式

每次不再喂 3 张图，而是喂 $N+1$ 张：1 个 anchor、1 个 positive、$N-1$ 个 negatives。

$$
\mathcal{L}_{\text{N-pair}} = -\log \frac{\exp(f(a)^\top f(p))}{\exp(f(a)^\top f(p)) + \sum_{j=1}^{N-1} \exp(f(a)^\top f(n_j))}
$$

### 这个形式眼熟吗？

**你应该一眼认出：这就是 softmax 交叉熵！**

让我把它"翻译"回你熟悉的分类问题：

- 想象一个 $N$ 类分类器，类别就是 $\{p, n_1, n_2, \ldots, n_{N-1}\}$ 这 $N$ 个候选。
- 每个候选的 logit 是 $f(a)^\top f(\text{候选})$（anchor 与候选的内积，相当于"匹配度"）。
- 真实标签是 "positive 是正确答案"。
- 用 softmax + 交叉熵优化。

> 💡 **对比学习从此有了一个全新身份：它就是个分类问题，分类的目标是"在这 N 个候选里找出 positive"。**

### 关键进步

- **一次对比 N 个候选**——监督信号比 Triplet 强 N 倍。
- **不需要 margin 这个超参**——softmax 自动控制距离。

### 短板

N-pair 还是要**手工组织** (a, p, n₁, ..., n_{N-1}) 这样的"成组样本"。工程上比 Triplet 好一些，但还是麻烦。

更深的问题：负样本必须**事先知道是 negative**，需要标注或某种额外信号。

→ **能不能用一种更优雅的方式自动产生大量 negatives？**

## 四、第三棒：InfoNCE（van den Oord et al., 2018）—— 对比学习的标准答案

### 数学形式

$$
\boxed{\ \mathcal{L}_{\text{InfoNCE}} = -\log \frac{\exp(\text{sim}(q,\, k^+) / \tau)}{\sum_{i=0}^{N} \exp(\text{sim}(q,\, k_i) / \tau)}\ }
$$

注意：求和符号里的 $i=0$ 到 $N$ 一共是 $N+1$ 项——其中 $k_0 = k^+$ 是正例，$k_1, \ldots, k_N$ 是 N 个负例。

### 逐项拆解

| 符号 | 含义 |
|---|---|
| $q$ | query（查询向量），通常是 anchor 视图的表征，已 L2 归一化 |
| $k^+$ | positive key，与 $q$ 是同一物体的另一视图的表征 |
| $k_i$ | 第 $i$ 个 key 候选（包含 1 个正例 + N 个负例） |
| $\text{sim}(\mathbf{u}, \mathbf{v}) = \mathbf{u}^\top \mathbf{v}$ | 由于已归一化，等价于余弦相似度 |
| $\tau$ | temperature（温度系数），常取 0.07 ～ 0.1，控制 softmax 锐度 |
| 分子 | $q$ 与正例的相似度的 exp |
| 分母 | $q$ 与所有候选（正 + 负）的相似度的 exp 之和 |

### 它就是 (N+1) 类 softmax 分类

请仔细看一眼公式形状：

$$
-\log \frac{\exp(\text{logit}_{\text{正确}})}{\sum_i \exp(\text{logit}_i)}
$$

这就是教科书上的 softmax 交叉熵。所以 InfoNCE 在做的事**和你训练 ImageNet 分类器一模一样**——只是分类的 N 个类别不再是"猫狗鸟"，而是"这一 batch 里的 N+1 个候选 key"。

> 🎯 **InfoNCE 的精髓**：把对比学习重新表述为**带噪声的分类问题**（NCE = Noise Contrastive Estimation），从而可以用最熟悉的 softmax 交叉熵直接训练。

### Temperature τ 在干什么？

$\tau$ 是 InfoNCE 里**最容易被忽视、但对效果影响巨大**的超参。

考虑两个极端：

- $\tau \to \infty$：相似度被压平，所有候选的 logit 接近，softmax 接近均匀分布 → 模型学不到东西。
- $\tau \to 0$：相似度被拉到极端，softmax 变成 one-hot，对最相似的那个候选给极高权重 → 训练不稳定，且对**hard negative**（最像正例的那个负例）过度敏感。

实践中 $\tau \in [0.05, 0.2]$。**CLIP 把 $\tau$ 设为可学习参数**——这是个聪明的设计，模型自己找到合适的锐度。我们第 4 章会再讲。

### 为什么叫 "Info" NCE？

InfoNCE 这个名字来自 van den Oord 在 CPC（Contrastive Predictive Coding）论文里证明的一个性质：

> **最小化 InfoNCE 损失 ≈ 最大化 query 和 positive key 之间的互信息（mutual information）下界。**

也就是说，InfoNCE 不只是"长得像 softmax"——它有信息论的理论基础，证明它在做"提取最大化互信息的表征"。这给了对比学习一份理论合法性。

公式（不需要懂细节，知道有这个东西即可）：

$$
I(q; k^+) \geq \log N - \mathcal{L}_{\text{InfoNCE}}
$$

含义：负样本数 $N$ 越大，互信息下界越紧、表征越好。这正好对应下面要讲的"为什么负样本越多越好"。

## 五、最关键的工程直觉：负样本越多越好

这一句话，你需要刻在脑子里。它会在第 3 章 SimCLR、第 4 章 CLIP 里反复出现：

> 💡 **负样本越多 → 分母里的"陪跑选手"越多 → (N+1) 类分类任务越难 → 模型被迫学到更精细的判别能力。**

### 一个直观例子

想象你是一个面试官：

- **N=1**（Triplet）：每次让候选人和**1 个对手**比，谁强录用谁。这种比较太简单，水平差不多的人都能被招进来。
- **N=4096**（SimCLR）：每次让候选人和**4096 个对手**比，必须"在所有人里最匹配岗位"才能录用。这种筛选极严苛，只有真正合适的能通过。

模型也是一样：负样本越多，**"被选中"这件事的信息量越大**，模型必须学到更精细的判别能力才能完成任务。

### 这一直觉直接催生了三个工程趋势

1. **SimCLR**（2020）：把 batch size 拉到 4096 → 同 batch 内所有其他样本都是负例。
2. **MoCo**（2020）：用一个 queue 存储**历史 batch 的表征**作为负例池，突破了 GPU 显存的 batch size 上限。
3. **CLIP**（2021）：分布式训练，**batch size = 32768**（32K！）。每张图同时和 32767 段文本对比。

> CLIP 的成功有一半要归功于"我们能负担得起 32K 的 batch size"这件事。

### Batch size 与精度的实证关系

SimCLR 论文的 Figure 9 给出了一张著名的图：

```
ImageNet top-1 (linear probe)
70% ┤              ╱━━━
    │           ╱╱
65% ┤        ╱╱
    │     ╱╱
60% ┤   ╱
    │ ╱
55% ┤
    └────┬────┬────┬────┬────────
         256  512 1024 2048   4096   batch size
```

batch size 从 256 → 4096，下游 ImageNet 精度提升 **8 个百分点**。这不是边际改进，这是**质变**。

## 六、把第 1 课和本章串起来

| 第 1 课的世界观 | 本章的数学翻译 |
|---|---|
| "同物近、异物远" | $\text{sim}(q, k^+) > \text{sim}(q, k_i)$ |
| 数据增强造 positive | $q$ 和 $k^+$ 是同一原图的两个视图的表征 |
| 不需要标签 | 正负例由"是否同源"自动产生 |
| 学"什么变化重要" | 模型必须把表征中的"无关变化"压平，让 $q$ 和 $k^+$ 总能对上 |

### 一张总览图

```
                    InfoNCE Loss

                  ┌─── 分子 ─────┐
                  │  exp(q·k⁺/τ)  │     ← 把"正例"那一项的得分凸出来
                  └───────────────┘
        L = -log ──────────────────
                  ┌─── 分母 ─────┐
                  │  Σ exp(q·kᵢ/τ) │    ← 所有候选的得分总和（归一化）
                  └───────────────┘

           ↑                                     ↑
        把 positive                          把所有候选做归一化，
        的相似度推高                         相当于做 (N+1) 类分类
                                                 ↑
                                       N 越大 → 任务越难 → 表征越好
```

## 七、本章一句话总结

> 🎓 **InfoNCE = 把对比学习包装成 (N+1) 类 softmax 分类。正例是真答案，负例是干扰项；负例越多越难，也越好。**

这一句直接撑起 CLIP 损失函数。下一章我们看 **SimCLR 怎么把这个 loss 真正跑起来**——你会看到一个完整的对比学习管线，以及三个反直觉的工程细节。

## 📋 参考答案

<details>
<summary>点开看 Q1 参考</summary>

- **分子** $\exp(\text{sim}(q, k^+)/\tau)$：把"正例"那一项的相似度凸出来——它越大，loss 越小（取负 log 后）。
- **分母** $\sum \exp(\text{sim}(q, k_i)/\tau)$：所有候选（包含正例和负例）相似度的归一化项。它扮演 softmax 分母的角色。
- **本质就是 softmax**：把分子分母合在一起就是 softmax 函数 $\frac{\exp(z_y)}{\sum_i \exp(z_i)}$，其中 $z_y$ 是"正确类别"的 logit。所以 InfoNCE 等价于在 (N+1) 个候选里做 softmax 交叉熵分类。
</details>

<details>
<summary>点开看 Q2 参考</summary>

先把所有相似度除以 $\tau = 0.1$：
- $0.9/0.1 = 9$
- $0.5/0.1 = 5$
- $0.3/0.1 = 3$
- $0.1/0.1 = 1$

然后取 exp：
- 分子：$\exp(9) \approx 8103$
- 分母：$8103 + 148 + 20 + 2.7 \approx 8274$

InfoNCE：

$$
\mathcal{L} = -\log \frac{8103}{8274} \approx -\log(0.979) \approx 0.021
$$

很小的 loss——因为正例的相似度（0.9）已经远高于所有负例（最大 0.5），模型预测得很自信。

**对比一下**：如果 $\tau = 1$（不除），分子 $\exp(0.9) \approx 2.46$，分母 $\approx 2.46 + 1.65 + 1.35 + 1.11 \approx 6.57$，loss = $-\log(2.46/6.57) \approx 0.98$。

→ **同样的相似度差距，τ 小 → loss 信号锐利；τ 大 → loss 信号平坦。** τ 直接控制了模型对"差距大小"的敏感度。
</details>

<details>
<summary>点开看 Q3 参考</summary>

**信息论角度**（CPC 论文的证明）：

$$
I(q; k^+) \geq \log N - \mathcal{L}_{\text{InfoNCE}}
$$

$N$ 越大，互信息下界越紧——也就是说我们对"$q$ 和 $k^+$ 共享了多少信息"的估计越准。所以负样本多 → 表征学习的目标更精确。

**分类问题角度**：

- N=1：二分类，瞎猜也有 50% 准确率，模型没压力。
- N=1000：1001 类分类，瞎猜准确率 0.1%，模型必须学到非常精细的特征才能"在 1000 个干扰项里选对"。

这就是为什么 SimCLR 要 4096 batch、CLIP 要 32K batch——**用更难的分类任务逼出更好的表征**。
</details>

<details>
<summary>点开看 Q4 参考</summary>

**$\tau$ 很小的现象**：

- softmax 变得**极度尖锐**——几乎是 one-hot 分布，所有概率质量集中在最相似的那个候选上。
- 训练时模型对**hardest negative**（最像正例的负例）过度敏感——一个小的相似度变化会引起巨大的梯度。
- 容易**训练不稳定**，loss 振荡。

**$\tau$ 太大的现象**：

- softmax 变平，所有候选概率接近均匀。
- 梯度信号弱，模型学得慢。
- 学到的表征**判别力不足**——没有把正负例区分得足够开。

**CLIP 的启发**：既然 $\tau$ 这么关键、又依赖具体数据分布和 batch size，**让模型自己学**最好。CLIP 把 $\tau$ 实现为一个 `log-temperature` 标量参数（避免数值溢出）：

```python
# CLIP 源码片段
self.logit_scale = nn.Parameter(torch.ones([]) * np.log(1 / 0.07))
# 实际 1/τ = exp(logit_scale)
```

并且 `clamp(logit_scale.exp(), max=100)` 避免它学到太极端的值。
</details>
