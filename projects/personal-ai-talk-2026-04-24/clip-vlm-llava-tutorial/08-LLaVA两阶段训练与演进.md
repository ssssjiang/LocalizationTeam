# 📘 第 8 课：LLaVA 两阶段训练与演进

> 学习目标：理解 LLaVA 的两阶段训练流程；看清 LLaVA-1.5 / NeXT / OneVision 的演进逻辑。
>
> 重点：**为什么必须两阶段、每阶段在解决什么问题、训练成本为何这么低**。
>
> 预计阅读时间：30 分钟。读完本章，你能复盘 LLaVA 整个训练管线，并能评估"自己训一个 LLaVA"需要多少资源。

## 一、为什么必须分两阶段

### 一阶段训练的问题

如果一上来就用 158K 高质量指令数据 + 端到端微调（投影器 + LLM 一起训），会出现两个问题：

**问题 1：投影器还没学会"翻译"，LLM 就被改坏了**

- 投影器初始是随机的——它输出的视觉 token 在 LLM 的 word embedding 空间里是**完全无意义的噪声**
- LLM 看到这些噪声 token，一开始会被强迫"在噪声里找模式"
- 这会**扰动 LLM 原有的语言能力**——梯度反传会把 LLM 的权重往"适应噪声"的方向推

**问题 2：158K 数据太少，不足以同时训两个东西**

- 158K 多模态数据 vs LLM 参数量 7B
- 如果让 LLM 也跟着调，数据量太少，容易过拟合到这 158K 的对话风格上
- 模型的语言推理能力会下降

### 两阶段的设计哲学

LLaVA 论文的解法是**先"对齐"再"对话"**：

```
┌──────────────────────────────────────────────────────┐
│  阶段一：Feature Alignment Pre-training              │
│                                                      │
│  目的：训投影器，让它学会"把 CLIP 视觉特征翻译成      │
│        LLM 能理解的伪 word embedding"                │
│                                                      │
│  数据：558K 简单 caption 对（CC3M 子集）              │
│  训练：只训 W（投影器），CLIP 和 LLM 都冻结           │
│  时间：~4 小时（8×A100）                              │
└──────────────────────────────────────────────────────┘
                         ↓
┌──────────────────────────────────────────────────────┐
│  阶段二：Visual Instruction Tuning                   │
│                                                      │
│  目的：训整个对话系统（投影器 + LLM），让模型学会     │
│        "看图聊天、跟随指令、复杂推理"                 │
│                                                      │
│  数据：158K GPT-4 生成的指令数据                      │
│  训练：训 W + LLM（CLIP 仍冻结）                     │
│  时间：~10 小时（8×A100）                             │
└──────────────────────────────────────────────────────┘
```

**两阶段的分工**：

- **阶段一只解决"对齐"**：让投影器把 CLIP 输出"翻译"成 LLM 能听懂的语言。这是个**简单任务**，不需要高质量数据，只需要海量"图 + 简单 caption"对。
- **阶段二只解决"对话"**：在已经对齐的基础上，教模型怎么基于图回答问题。这需要**高质量数据**，但量可以少。

> 🎯 **类比**：
>
> 阶段一 = 教外国留学生**学拼音和基本词汇**（用大量简单文本，重复练习）
> 阶段二 = 教学生**写作文**（用少量高质量范文，学习篇章结构）
>
> 一阶段就让学生写作文 = 必然失败。

## 二、阶段一：Feature Alignment Pre-training

### 数据：CC3M 子集 558K 对

**Conceptual Captions 3M (CC3M)** 是 Google 出的图文数据集，340 万对图 + 简单 caption，从 web alt-text 爬取并清洗。

LLaVA 从中选了 **558K** 对（论文说"过滤掉太复杂的、保留简单清晰的"）。

数据格式：
```
图像: cc3m_image_001.jpg
Caption: "A dog running on the beach at sunset."
```

### 训练目标

把这 558K 对包装成"指令格式"：

```
Human: <image>\n请简短地描述这张图。
Assistant: A dog running on the beach at sunset.
```

其中 `<image>` 是占位符，实际会被替换成 256 个视觉 token（投影器输出）。

**训练 loss**：标准的 next token prediction（自回归生成 caption）

$$
\mathcal{L}_{\text{stage1}} = -\sum_{i} \log p(\text{caption}_i \mid \text{visual tokens}, \text{prompt})
$$

### 谁在训、谁冻结

| 组件 | 状态 |
|---|---|
| CLIP-ViT-L/14 | ❄️ 冻结 |
| Linear Projector W | 🔥 训练（新增的 ~5M 参数） |
| Vicuna LLM | ❄️ 冻结 |

**只有投影器 W 在更新**。

### 这一步学到了什么

经过 558K 对训练，投影器 W 学会了：

> **把 CLIP-ViT 输出的视觉 token（包含"图里有什么"的视觉语义），翻译成 LLM word embedding 空间里"对应词汇"的 embedding。**

举例：
- 一张猫的图 → CLIP 输出 256 个 patch token → 投影器 W → 256 个伪 word embedding，这些 embedding 在 LLM 的语义空间里**最接近 "cat", "fur", "whiskers", "sitting"** 等词的 embedding

LLM 拿到这些"伪 word embedding"，在自己的语言空间里就**能继续推理**——它不知道这是图，但它知道"这些 token 表达的语义就像这些词一样"。

### 训练超参

| 超参 | 值 |
|---|---|
| Batch size | 256 |
| 学习率 | 2e-3 |
| Epoch | 1 |
| Optimizer | AdamW |
| 训练时间 | **~4 小时（8×A100 80G）** |

学习率特别高（2e-3，是常规 LLM 微调的 100 倍）——因为只训一个新增的小投影器，可以激进。

## 三、阶段二：Visual Instruction Tuning

### 数据：158K GPT-4 生成

第 7 章详细讲过：

| 类型 | 数量 |
|---|---|
| Conversation | 58K |
| Detailed Description | 23K |
| Complex Reasoning | 77K |
| **总计** | **158K** |

每条数据格式：

```yaml
图像: coco_image_007.jpg
对话:
  Human: 图里的人在做什么？
  Assistant: 男士在公园里遛一只金毛犬。
  Human: 是什么季节？
  Assistant: 从树叶颜色判断，应该是初秋。
  ...
```

### 训练目标

仍然是 next token prediction，但只对 **Assistant 的回答部分** 计算 loss：

$$
\mathcal{L}_{\text{stage2}} = -\sum_{t \in \text{Assistant tokens}} \log p(x_t \mid x_{<t}, \text{visual tokens})
$$

> 注意：Human 的问题部分不算 loss（不让模型学怎么"问问题"，只学怎么"回答"）。

### 谁在训、谁冻结

| 组件 | 状态 |
|---|---|
| CLIP-ViT-L/14 | ❄️ 冻结 |
| Linear Projector W | 🔥 训练（继承阶段一的权重） |
| Vicuna LLM | 🔥 训练 |

**这阶段 LLM 也开放训练**——目的是让 LLM 适应"看图回答"的对话风格。

### 训练超参

| 超参 | 值 |
|---|---|
| Batch size | 128 |
| 学习率 | 2e-5（**比阶段一低 100 倍**） |
| Epoch | 3 |
| 训练时间 | **~10 小时（8×A100 80G）** |

学习率要低很多——因为 LLM 已经训好了，我们只想"轻微微调"，不能破坏原有能力。

### 这一步学到了什么

阶段二让模型学到：

1. **指令跟随**：理解 "请详细描述"、"用诗歌的形式"、"回答简短" 等元指令
2. **多轮对话**：能维持上下文，回答连续问题
3. **复杂推理**：根据视觉信息做因果推断、属性判断、常识应用
4. **风格对齐**：回答的语气、格式、结构匹配 GPT-4 的标准

## 四、为什么 LLaVA 训练这么便宜

### 完整训练成本

```
阶段一: 8 × A100 (80G) × 4 小时   ≈ 32 GPU·hours
阶段二: 8 × A100 (80G) × 10 小时  ≈ 80 GPU·hours
─────────────────────────────────────────────
总计:                              ≈ 112 GPU·hours
```

按云服务价格 ~$3/A100·hour 算，**完整训练成本约 $300-400**。

学术实验室、小公司、个人研究者**都付得起**。

### 对比其他 VLM

| 模型 | 训练资源（估算） | 数据规模 |
|---|---|---|
| **LLaVA-v1** | 112 GPU·hours | 716K |
| BLIP-2 | ~10000 GPU·hours | 129M |
| Flamingo | ~100000 GPU·hours | ~2.3B |
| GPT-4V | ?（OpenAI 闭源） | ?（估计 ~10⁵+ GPU·hours） |

**LLaVA 比 BLIP-2 便宜 100 倍，比 Flamingo 便宜 1000 倍。**

### 为什么这么便宜？

回顾第 7 章讲的设计哲学：

1. **CLIP-ViT 已经训好了**——免去视觉编码器训练（这是 OpenAI 已经付了 $几百万 训出来的成果）
2. **Vicuna 已经训好了**——免去 LLM 训练（这是 Meta 付了 $几百万 训出来的成果）
3. **只训一个 5M 投影器（阶段一）+ 微调 7B LLM（阶段二）**

> 🎯 **LLaVA 是站在两个巨人肩膀上的产物**。它的便宜，是因为它**不重复造轮子**。

### 对学术界的意义

LLaVA 证明了：

> **多模态对话模型不再是巨头公司的专利。**

学术实验室、小型创业公司、甚至个人开发者，都能：
- 在自己的数据上微调 LLaVA
- 适配垂直领域（医学、法律、教育）
- 改进特定能力（OCR、图表理解、视频理解）

这直接催生了开源 VLM 的繁荣。

## 五、LLaVA-1.5 的关键升级

LLaVA-v1 出来 6 个月后（2023.10），同一作者团队推出 LLaVA-1.5，性能大幅提升。

### 改了什么

LLaVA-1.5 论文 ("Improved Baselines with Visual Instruction Tuning") 没改架构哲学，**做了 4 个工程改进**：

#### 改进 1：MLP 投影器（替代 Linear）

**LLaVA-v1**：投影器是单层线性 W ∈ ℝ^(1024 × 4096)
**LLaVA-1.5**：投影器是两层 MLP

```python
# LLaVA-v1
projector = nn.Linear(1024, 4096)

# LLaVA-1.5
projector = nn.Sequential(
    nn.Linear(1024, 4096),
    nn.GELU(),
    nn.Linear(4096, 4096),
)
```

**为什么涨点**：

- 单层 Linear 只能做线性变换，表达能力有限
- 两层 MLP 加 GeLU 非线性，能学更复杂的"翻译规则"
- 多了 ~17M 参数，但相对 7B LLM 几乎不影响成本

**实测涨点**：MM-Vet 基准 +2.0 分

#### 改进 2：更高分辨率（224×224 → 336×336）

**LLaVA-v1**：CLIP-ViT-L/14, 224×224，输出 256 个 patch token
**LLaVA-1.5**：CLIP-ViT-L/14, 336×336，输出 576 个 patch token

**为什么涨点**：

- 高分辨率 = 更多视觉细节
- 对 OCR、细粒度物体识别帮助巨大（"招牌上写什么字"、"螺丝是几号的"）

**实测涨点**：TextVQA +5.4 分

代价是：
- 视觉 token 数从 256 → 576，LLM 输入序列长 2.25 倍
- 训练和推理慢一些

#### 改进 3：加入学术 VQA 数据

**LLaVA-v1 数据**：158K GPT-4 生成 + 23K ScienceQA
**LLaVA-1.5 数据**：665K 混合数据
- 158K 原 GPT-4 数据
- 学术 VQA 数据集（VQAv2, GQA, OK-VQA, OCR-VQA, A-OKVQA, TextCaps, RefCOCO, VG）
- ShareGPT 纯文本对话（保持 LLM 语言能力）

**为什么涨点**：

- VQA 数据集覆盖更广（OCR、空间、计数、知识 QA）
- 短答案数据让模型学会"该简短时简短"
- 纯文本数据防止"灾难性遗忘"——避免 LLM 微调后只会回答图像问题，不会聊普通话题

**实测涨点**：综合性能涨 4-6 分

#### 改进 4：Vicuna-1.5 LLM

LLM 升级到 Vicuna-1.5（基于 LLaMA-2 微调），语言能力更强。

### LLaVA-1.5 性能

| 基准 | LLaVA-v1 | LLaVA-1.5 (7B) | LLaVA-1.5 (13B) |
|---|---|---|---|
| MM-Vet | ~30 | 30.5 | **35.4** |
| MMBench | ~36 | 64.3 | **67.7** |
| ScienceQA | 70 | 71.6 | **72.8** |
| TextVQA | 38 | 58.2 | **61.3** |

LLaVA-1.5 直接成为**开源 VLM 的事实标杆**——后续所有开源 VLM 都把 LLaVA-1.5 当作 baseline 比较。

## 六、LLaVA-NeXT 与 OneVision

### LLaVA-NeXT (2024.01)

LLaVA-1.5 的进一步演进。三个关键升级：

**升级 1：动态高分辨率（AnyRes）**

LLaVA-1.5 把所有图缩放到 336×336——会丢失高分辨率细节。

LLaVA-NeXT 引入**动态分辨率**：根据图的原始宽高，把图切成多个 336×336 的 patch grid，每个 patch 独立编码，然后拼起来。

```
原图 (1080×720)
       │
       ▼ 自适应切分
┌──────┬──────┬──────┐
│Patch1│Patch2│Patch3│   ← 每个 336×336
├──────┼──────┼──────┤
│Patch4│Patch5│Patch6│
└──────┴──────┴──────┘
       │
       ▼ 各自 CLIP 编码
   6 × 576 = 3456 个视觉 token
       │
       + 整图缩略 = 576 token
       │
       ▼ 喂给 LLM
   总共 4032 个视觉 token
```

**好处**：保留高分辨率细节，对 OCR、文档图像、复杂场景帮助巨大。
**代价**：视觉 token 数暴涨，推理变慢、显存占用增加。

**升级 2：更强 LLM 基座**

LLM 升级到 Mistral-7B, Yi-34B, LLaMA-3。

**升级 3：更多多样化数据**

加入 LAION-GPT-V、ShareGPT4V 等更高质量、更多样的数据。

### LLaVA-OneVision (2024.08)

LLaVA-NeXT 的"统一版"——把图像、多图、视频统一到一个模型里。

| 模态 | 处理方式 |
|---|---|
| 单图 | LLaVA-NeXT 的动态分辨率 |
| 多图 | 把每张图独立编码后拼起来 |
| 视频 | 抽帧（如 32 帧），每帧编码后拼起来 |

**OneVision 的核心 insight**：图像、多图、视频在底层都可以**统一为"一组视觉 token + 文本"**——LLM 不需要区分模态。

这与早期 VideoChat 等模型走的"专门设计视频处理模块"的路线相反——再次印证了 LLaVA 系列的设计哲学：**让 LLM 自己处理，不要预先压缩**。

## 七、LLaVA 系列演进总结

```
2023.04  LLaVA-v1
         │  Linear projector + 224 + 158K GPT-4 data
         │
         ▼
2023.10  LLaVA-1.5
         │  MLP projector + 336 + 665K mixed data
         │
         ▼
2024.01  LLaVA-NeXT
         │  AnyRes (动态分辨率) + 更强 LLM
         │
         ▼
2024.08  LLaVA-OneVision
            统一图像/多图/视频
```

**核心架构哲学始终不变**：CLIP-ViT (frozen) + Projector + LLM。

**演进的方向**：

1. **更细的视觉**（分辨率提升、AnyRes）
2. **更多数据**（学术 VQA、ShareGPT4V、合成数据）
3. **更强的 LLM**（Vicuna → Mistral → Yi → LLaMA-3）
4. **更广的模态覆盖**（单图 → 多图 → 视频）

**始终不做的事**：

- 用复杂的桥接器（Q-Former 类）
- 改 LLM 架构（cross-attention 注入类）
- 训练 CLIP-ViT

→ **简单是 LLaVA 路线最大的优势**。

## 八、本章一句话总结

> 🎓 **LLaVA 两阶段训练：阶段一用 558K 简单 caption 训投影器（学"对齐"），阶段二用 158K GPT-4 数据训投影器+LLM（学"对话"）。**
>
> 总训练成本仅 ~$300-400，比 BLIP-2 便宜 100 倍。

## 📋 参考答案

<details>
<summary>点开看 Q1 参考</summary>

**两个核心问题**：

**问题 1：投影器是随机初始化的，输出的视觉 token 是噪声**

如果一阶段把 158K 高质量数据 + 端到端微调一起做：
- 投影器还没学会"翻译"——它输出的视觉 token 在 LLM 的 word embedding 空间里**毫无意义**
- LLM 必须"在噪声里找模式"，梯度反传会推动 LLM 适应这些噪声
- 结果：LLM 原有的语言能力被破坏，模型变成"半瞎半哑"

**问题 2：158K 数据太少，不足以同时训两个组件**

- 投影器需要学的是"翻译规则"——简单任务但需要大量样本（558K 简单 caption 完美胜任）
- LLM 微调需要的是"任务适应"——复杂任务但只需少量高质量样本（158K 完美胜任）
- 两件事的"数据需求曲线"完全不同，强行用一份数据训两件事 → 都不会做好

**两阶段的精髓**：

把"投影器对齐"和"LLM 任务适应"**解耦**——各自用最合适的数据训最合适的组件。

→ 这是当前所有大模型微调（LoRA、QLoRA、Adapter Tuning）共享的核心哲学：**对不同的学习目标，用不同的数据和不同的可训练参数子集**。
</details>

<details>
<summary>点开看 Q2 参考</summary>

**为什么 CLIP-ViT 永远不微调**：

1. **它已经在 4 亿对上对齐过了**——CLIP-ViT 的视觉表征空间已经是"语言可描述的语义空间"。这个对齐质量来自巨量数据，不是 158K 数据能提升的。

2. **微调它会破坏对齐**——LLaVA 的 158K 数据相对 CLIP 训练数据规模差 2500 倍。在小数据上微调大模型，几乎一定会把它学坏（catastrophic forgetting）。

3. **冻结它能保持泛化**——CLIP-ViT 见过 4 亿种视觉概念，冻结它意味着 LLaVA 继承了这种泛化能力。如果微调，模型会过拟合到 158K 数据的视觉分布，泛化能力下降。

4. **节省训练成本**——CLIP-ViT-L/14 有 304M 参数，冻结它能节省大量梯度计算和显存。

**反例**：

如果数据规模够大（比如 1 亿+ 高质量多模态数据），微调 CLIP-ViT 是有意义的——可以让它适配新的对话任务。但 LLaVA 的设定下，**冻结永远是更安全的选择**。

**LLaVA-1.5 论文的实验确认了这点**：他们试过解冻 CLIP-ViT 微调，效果**反而下降**了 1-2 分。

→ **冻结预训练大模型 + 训练轻量桥接器** 是当前微调范式的金科玉律（除非你有海量数据）。
</details>

<details>
<summary>点开看 Q3 参考</summary>

**核心原因：防止灾难性遗忘**

LLaVA-v1 训完后有个问题：模型变得只会回答"关于图像的问题"，对纯文本对话能力下降。比如：
- 用户："你好，今天天气怎么样？"（无图）
- LLaVA-v1：可能回答得很奇怪、或硬要"看图回答"

为什么？因为微调阶段二的 158K 数据**100% 都是看图问答**——模型在长达 3 个 epoch 的训练中，学到了"输入永远包含图像 token"的强先验。这破坏了 Vicuna 原有的纯文本对话能力。

**LLaVA-1.5 的解法**：

在阶段二训练数据里**混入 ShareGPT 纯文本对话**（约 40K 条）。这样模型学到：
- 输入有图像 token → 看图回答
- 输入只有文本 → 像普通 LLM 一样回答

**这种"混合数据防遗忘"是当前所有指令微调的标配做法**：

- LLaMA 微调：混入预训练数据 + 指令数据
- LLaVA-1.5：混入文本对话 + 视觉对话
- Stable Diffusion 微调：混入原训练数据 + 新数据

→ **核心 insight**：微调时，要让模型既学新能力，又不忘旧能力。最简单的方法就是把"旧能力的代表性数据"按比例混入新数据。
</details>

<details>
<summary>点开看 Q4 参考</summary>

**任务**：给 LLaVA 加"理解中文表情包"能力。

**挑战分析**：

1. 中文表情包包含**视觉元素 + 中文文字 + 文化梗**
2. 原 LLaVA 用 Vicuna（英文为主），中文能力弱
3. CLIP-ViT 在英文图文对上训，对中文文字的理解可能弱
4. 表情包的"梗"涉及文化背景，需要常识推理

**方案**：

**步骤 1：选 / 训中文 LLM 基座**

- 候选：Qwen-7B / ChatGLM3 / Yi-6B（中文能力强的开源 LLM）
- 或者：用 LLaMA-3 + 中文指令微调

**步骤 2：选中文友好的视觉编码器**

- 候选：Chinese-CLIP（达摩院）—— 在中文图文对上训过，对中文文字理解更好
- 备选：原 CLIP-ViT-L 仍可，但 OCR 能力弱

**步骤 3：造数据**

- **种子数据**：收集 1-5 万张中文表情包 + 文字标注 + 表情含义
- **GPT-4 造数据**（参考 LLaVA 范式）：
  - 喂给 GPT-4：表情包的视觉描述 + 文字内容 + 含义
  - 让 GPT-4 生成多种"用户问、助手答"对话
  - 包括：解释表情包含义、推荐使用场景、识别情绪、解释文化梗

**步骤 4：两阶段训练**

- 阶段一：用 100 万对中文图文对（如 Wukong、LAION-Chinese）训投影器
- 阶段二：用步骤 3 造的几万条表情包指令数据训投影器 + LLM

**步骤 5：评估**

- 准备 1000 张测试表情包 + 人工标注的"标准回答"
- 评估指标：解释准确率、文化梗识别率、回答自然度

**资源估算**：

- 训练：8×A100 × 1 天 ≈ $400
- 数据：GPT-4 调用 + 人工核查 ≈ $1000-3000
- **总成本约 $1500-3500**

**这就是 LLaVA 范式的强大之处**——任何垂直能力都可以用这个流程低成本快速构建。

→ 实际上类似的工作已经存在（如 ChatGLM 的多模态版本、Qwen-VL 等），都遵循类似流程。
</details>
