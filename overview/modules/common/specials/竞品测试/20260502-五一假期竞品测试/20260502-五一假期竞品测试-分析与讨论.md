## 2. Navimow i206 AWD nRTK 的硬件配置（关键背景）

> 来源：Navimow 官方产品页 + i208 用户手册 §3.4

i206 AWD nRTK 实际有 **3 种工作模式**：

| 模式 | 卫星接收来源 | RTK 校正来源 | 默认/可选 |
| --- | --- | --- | --- |
| **A. 纯 Network RTK** | **机身内置 GNSS 天线** | 4G/蜂窝 → 云端 CORS 网 RTCM | 默认 |
| **B. nRTK + 可选外置天线** | 加装的外置 GNSS 天线（屋顶/墙上，连接到充电桩/机器） | 4G/蜂窝 → 云端 CORS 网 RTCM | 可选购"Antenna Extension Kit" |
| **C. Local RTK + 外置天线** | 外置 GNSS 天线 | 本地 RTK 基站 RTCM | 配件/调试模式 |

**关键事实**：
- 官方原话："Network RTK eliminates the need for traditional physical base stations"
- 用户手册 §3.4 标题就是 "Install the Antenna **(Optional)**"，且只在 "Network RTK service is **not supported in your area**" 才需要装外置天线
- **海外同事 A-5 测试时 i206 默认应是 A 模式**（无外置天线），所以"找树荫制造阴影"在原理上不可能成功
- **海外同事 A-7 测试时切到 C 模式**（"切到 Local RTK 模式 + 接 RTK 天线"），但用例本身没跑

## 4. 实测结果按用例 vs 设计意图

### A-5 桩位变化

| 用例 | 设计意图 | i210 LiDAR 实测 | i206 nRTK 实测 | 是否符合需求设计 |
| --- | --- | --- | --- | --- |
| 观察 1（建图中移桩） | 能否继续建图 + 能否回桩 | 可以；先回原位置 → 直接去新桩位置 | 可以；先回位置 0 → 左右旋转找新桩 | ✅ 已答 |
| 观察 2（割草中移桩） | 能否割完 + 是否出界 + 能否回桩 | 1m/3m 成功；位置 ② 旋转整圈未识别（**逆光**）→ **跑出地图外未及时报错** | 1m 成功；**3m 以外仅靠单目未能识别到桩** | ✅ 已答，**且暴露 2 条新现象** |
| 观察 3（桩上时态） | 同观察 2 | 可出桩；**APP 弹"桩位置变化"警告**；优先在原桩朝向 ±45° 找，最后 360° | — | ✅ 已答 |
| 观察 4/5/6（**仅 nRTK + 必须 RTK 阴影**） | 测真正 nRTK 模式下重置桩流程 | — | **i206 在大树下"未发现 RTK 信号丢失"，没真正进入阴影工况** | ⚠️ **执行偏离需求**（根因见 §2 + §5）|
| 观察 7（搬桩到无共视 B 区，激光/纯视觉） | 是否会重定位 / 建新图 / 沿用旧图 | **没重定位、不建新图，直接以桩为原点跑旧图**；沿边 2 圈才报出界 | 未做（YUKA Mini Vision 全部空） | ✅ 已答，**结论是负面**（无跨图全局重定位） |

### A-6 抱起重定位

| 用例 | i210 LiDAR | i206 nRTK | 关键发现 |
| --- | --- | --- | --- |
| 观察 1（原地放回） | **无明显重定位动作**，立即继续 + 一次绕障 | 未做 | 可能时间过短未触发；也可能纯靠 IMU 续推 |
| 观察 2a（搬到地图外） | **能看到桩→自动回**；看不到桩→不动报错 | **完全被动**，靠语音 + 弹窗 + 人工搬回；区域外 1m + 桩正对机器→**机器也不会动** | 两台对桩可见性都强依赖；**没有真正的"全局重定位"动作** |
| 观察 2b（建图未完成搬到外）| 抱着走的轨迹被记进地图边界 | 同样问题：抱着走的轨迹算进边界，落地后边界是抱起 ↔ 放下两点连线 | **建图被污染**，需求里没单列这条用例 |

## 5. 关键现象 → 算法侧推断

| # | 现象 | 推断 | 置信度 |
| --- | --- | --- | --- |
| ① | i206 nRTK 桩搬到 3m 以外**仅靠单目无法识别** | i206 桩识别走**单目视觉**，作用距离上限 ~3m；不是激光/RTK 解算 | **高**（测试人员原话已写"仅靠单目"）|
| ② | i206 "重置桩位置"流程：搬回桩 → 退桩 → 自转一周 → 校准 | 桩重定位走**视觉里程计 + 桩 visual landmark 重新对准 + 自转扩视场**模式 | 高 |
| ③ | i210 LiDAR 搬到无共视 B 区，**不重定位、不建新图**，沿用旧图 | i210 LiDAR **没实现跨地图全局重定位**，定位 = LiDAR 局部 odom + 桩为锚点；**地图全局坐标 = "桩位置 + 桩朝向"** | **高**（A-5 观察 7 直接证实） |
| ④ | i210 LiDAR 出桩瞬间 APP 位置在 实际位置 ↔ 原桩位置之间跳一次 | 桩上属于"已知位姿"分支，离桩瞬间切到融合分支，**位姿融合权重突变** → 视觉看到一次位置 step | 中-高 |
| ⑤ | i210 LiDAR 抱起原地放下：无明显重定位动作 | 提起检测短时（< 阈值，可能 5-10s）+ 落地后 IMU/odom 直接续推；**未触发完整重定位** | 中（需多时长测试确认） |
| ⑥ | i210 LiDAR 找不到桩会冲出边界且**不报错** | 桩搜索失败 → 退化为按地图边界估计走，但因为定位飘了所以走出去；**异常检测/兜底逻辑缺失** | 中 |
| ⑦ | i206 nRTK 重定位成功后**不续割断点，从当前位置开始** | 重定位与任务规划是**解耦**的：重定位只更新位姿、不回滚到上次任务断点 | 中 |
| ⑧ | i206 nRTK 在大树下未掉 RTK | **直接根因**：nRTK 校正源在云端（4G），与天空遮蔽无关；要断必须断网或屏蔽机身 GNSS 天线 | **高**（与产品文档一致） |

### "RTK 全局坐标 vs 激光靠桩获取全局坐标"判据

| 现象 | 含义 |
| --- | --- |
| 激光机型搬到无共视 B 区，机器仍按"桩为原点"工作 | 激光机型 = 桩锚点全局对齐，无 LiDAR-based relocalization |
| RTK 机型搬到任意位置 + RTK 在线 → 直接定位准确，无需桩 | RTK 走全局坐标，桩仅对接 |
| RTK 机型在 RTK 阴影区 + 搬动 → 仍能定位 | 有视觉/桩 fallback |
| RTK 机型在 RTK 阴影区 + 搬动 + 黑胶带遮双目 → 失败 | **fallback 是双目视觉**（A-7 7M-3 / 7W-3 的核心判据） |

## 6. 重定位动作分类（整理用，写到测试需求 v2）

测试时按下表勾选：

| 类别 | 行为 | 已观察到的实例 |
| --- | --- | --- |
| **A. 无任何动作** | 放下即定位正确 | i206 A-5 观察 4「重定位成功」 |
| **B. 隐式** | APP 位置跳变 / 短暂错位再修正 | i210 A-5 观察 3「出桩 APP 跳一次」 |
| **C. 显式·短动作** | 绕障 / 小范围晃动 | i210 A-6 观察 1「绕障动作」 |
| **D. 显式·完整流程** | 自转 360° / 移动找标 / 停下扫视场 | i206 A-5 观察 5「退桩 + 自转一周校准」 |

> **注**：左右 45° / 360° 找桩 ≠ 位姿重定位；机器位姿是确定的，**只是不知道桩在哪**。这是「桩搜索」行为，不要和「位姿重定位」混淆。

每条观察项都加 2 栏：`重定位动作类别（A/B/C/D）` + `动作耗时（秒）`。

## 7. 强制制造"RTK 阴影"的可行方案（按工作模式区分）

| 工作模式 | 有效操作 | 无效操作 |
| --- | --- | --- |
| **A. 纯 nRTK** | ① **拔机器 SIM 卡 / APP 切飞行模式 / 关 4G**<br>② **铝箔多层包裹机身 GNSS 天线区域（顶部）** | ❌ 找树荫 / 屋檐<br>❌ 盖"基站"（无基站可盖） |
| **B. nRTK + 外置天线** | ① 同 A 断 4G<br>② **铝箔/铁罐完全包裹外置天线头**（屋顶/墙上的白色蘑菇头） | 同上 |
| **C. Local RTK** | ① **拔基站电源**<br>② **铝箔完全包裹基站天线**<br>③ **拔机器到基站的连接** | 找树荫 / 屋檐 |

### 屏蔽材料对比

| 材料 | 原理 | 推荐度 | 备注 |
| --- | --- | --- | --- |
| **铝箔（厨房用）** | 法拉第笼屏蔽 GNSS 1.1~1.6GHz | ⭐⭐⭐ 最推荐 | 至少 3 层 + 胶带封缝；**不能留缝**（缝 < 2cm 基本 OK）|
| **不锈钢锅 / 饼干铁罐** | 同上 | ⭐⭐ | 比天线大、能完全扣住、再用铝箔封缝 |
| **铝箔 + 金属罐双层** | 同上 | ⭐⭐⭐ 保险 | 几乎完全屏蔽 |
| 塑料盖 / 玻璃盖 / 纸盒 | — | ❌ 无效 | 必须金属 |

### 验收硬门槛

任何屏蔽方案启用后：
- **APP RTK 状态**从 FIX → FLOAT / SINGLE / NO FIX 任一
- **持续 ≥ 30 秒**
- 否则该用例**作废重测**（加强屏蔽：多层铝箔 / 换金属罐 / 同时断网）

## 8. 测试需求遗漏点（按价值排序）

### P0（必补）
1. **每条观察项加"重定位动作类别 + 耗时"两栏**：把"放下即成功"和"自转一周校准"分开记
2. **A-7 前置条件硬门槛**：APP RTK 状态字降级 ≥ 30s 才算阴影成立，否则作废
3. **A-7 SOP 区分 nRTK / Local RTK 模式**：不同模式制造阴影方法完全不同（见 §7）
4. **A-7 预备诊断用例（5 分钟成本）**：纯 nRTK 模式下 → 盖基站 → 观察 APP RTK 状态字是否变化。**做完即可定性证实 nRTK 不依赖自建基站**

### P1（强烈建议补）
5. **A-6 新增观察 3「建图时被提起」**：建图中抱起 → 走 5m → 放下 → 看建出来的地图边界是否包含空中轨迹
6. **A-5 新增观察 8「桩识别有效距离扫描」**：固定阴影区，桩从 0.5m 步进到 5m，每个距离正对/偏 ±30°/±60° 各 3 次，定量化桩识别能力
7. **每条用例加「失败时机器/APP 行为是否合理」栏**：现状只问成功/失败；i210 跑出地图外不报错、i206 区域外冲出边界无提示，都属于体验问题
8. **每条重定位用例加「重定位后是否续割原任务/进度是否保留」栏**：A-5 观察 4 i206 重定位成功但不续割，需求里没问

### P2（有空再补）
9. **「提起检测时长阈值」专项**：抱起 1s/3s/5s/8s/12s 五档 × 3 次，测触发提起检测的阈值和提起检测后能否退出
10. **APP 警告体验记录**：i210 弹"Location changed"、i206"重置桩位置"流程，是否给了正确提示 / 是否引导用户操作
11. **多次反复抱起 + 抱起+旋转 90°/180° 放回**：A-6 观察 1 只测了单次抱起原地放回

## 9. 给海外同事的"补测试 RTK 阴影" 操作 SOP（可直接转发）

```text
A-7 RTK 阴影测试 SOP（i206 AWD nRTK）

第 1 步：确认当前 RTK 工作模式
  ① 打开 APP → 设置 → 网络 / RTK 模式
  ② 截图记录："Network RTK" / "Local RTK" / 是否安装了外置天线

第 2 步：建立"真正的 RTK 阴影"（不能再用找树荫的方式）

  情况 ① 纯 Network RTK 模式（无外置天线）：
    - 拔机器 SIM 卡 或 APP 切飞行模式 或 关 WiFi
    - 用铝箔（至少 3 层）完全包裹机身顶部 → 胶带封缝
    - 等 30 秒，看 APP RTK 状态字

  情况 ② Local RTK 模式（有外置天线）：
    - 用铝箔完全包裹外置天线头 + 拔基站电源
    - 等 30 秒，看 APP RTK 状态字

第 3 步：验收（必须满足才算阴影建立）
  - APP RTK 状态：从 FIX → 变成 FLOAT / SINGLE / NO FIX 任一
  - 持续 ≥ 30 秒
  - 不满足 → 该用例作废，重新加强屏蔽（多层铝箔 / 换金属罐）

第 4 步：在阴影建立后才开始跑 7M-1 / 7W-1 等用例
  - 测试期间持续监控 RTK 状态字（防止屏蔽中途失效）
  - 每个用例都截图状态字
```
