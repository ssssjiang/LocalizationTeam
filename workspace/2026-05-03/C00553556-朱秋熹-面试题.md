## 一、针对项目提问

### A. 4D Radar SLAM（硕士研究，2023.01-2023.05）— 重点深挖

> **简历亮点**：PCA+RANSAC 地面提取过滤 ghost points；后端加闭环检测+地面约束+IMU 预积分提高 z 轴精度；评估不同前端匹配算法。

#### Q1. 4D Radar 与 3D LiDAR 在 SLAM 输入上的本质差异有哪些？这些差异如何反过来约束你的算法选择？

**参考答案要点**：
- 差异：(1) 点云稀疏（每帧 ~几百到几千点 vs LiDAR 数十万）；(2) 多径与镜面反射严重，产生 ghost points；(3) 多了一维 Doppler 速度（径向）；(4) 角度分辨率低（尤其俯仰角），但穿透雨雾烟尘能力强；(5) 测距噪声大（cm-dm 级 vs LiDAR mm-cm 级）。
- 算法影响：稀疏点云使 ICP/NDT 配准退化（对应不稳定）→ 倾向用 scan-to-submap 或基于 Doppler 的运动估计；ghost points 必须前端过滤；俯仰精度低 → z 轴飘移大，需要地面约束/IMU 兜底。

#### Q2. PCA 和 RANSAC 在地面提取里各自扮演什么角色？为什么需要两者结合，单用 RANSAC 不行吗？

**参考答案要点**：
- PCA：对候选地面点求协方差矩阵，最小特征值对应的特征向量即法向量；用来判断**这块点是否真的"平"**（特征值比 \(\lambda_3 / \lambda_1\) 足够小）。
- RANSAC：在含外点的全部点中**估计平面参数**（鲁棒拟合）。
- 单用 RANSAC 的问题：4D Radar 点稀疏 + ghost points 多，RANSAC 容易把"穿地"的虚点也拟合进平面或拟合到墙面/车顶；先用 PCA 在局部 patch 筛掉非平面区域（或筛初值），再 RANSAC 全局拟合，鲁棒性更好。
- 追问：怎么定 inlier 阈值？模型迭代次数？

#### Q3. 什么是 ghost points？4D Radar 哪些机制产生 ghost？你的过滤策略效果如何量化？

**参考答案要点**：
- 来源：(1) 多径反射（信号经地面/墙面二次反射）；(2) 相邻目标的 sidelobe；(3) 镜面强反射目标后方的"鬼像"；(4) 速度模糊产生的 Doppler 假目标。
- 过滤：地面下方点直接剔除（地面约束）；Doppler 一致性检查（静态点的径向速度应等于 \(-v_{ego} \cdot \hat{r}\)）；RCS 阈值；时序一致性。
- 量化：保留率/虚警率、对配准残差的影响；候选人若没量化只说"提高了精度"是减分项。

#### Q4. 后端图优化里，闭环 + 地面约束 + IMU 预积分各自加什么因子？z 轴精度具体提升了多少？

**参考答案要点**：
- 闭环：相对位姿因子 \(T_{ij}\)；地面约束：单边因子 \(z_i = 0\) 或 roll/pitch 接近 0（限制 3 自由度）；IMU 预积分：相邻关键帧的速度+位姿因子，限制 9 自由度（位姿+速度）。
- 信息矩阵权重怎么定？数据集量化指标（KITTI 类的 ATE/RPE，或自采）？
- 警惕回答：只加约束不分析信息矩阵就是表面理解。

#### Q5. IMU 预积分在 4D Radar 帧率（通常 10-20 Hz）下相比直接积分的优势？预积分量有哪些？怎么处理 bias 更新？

**参考答案要点**：
- 优势：避免每次优化重新积分整段 IMU；预积分量 \(\Delta R, \Delta v, \Delta p\) 在 body 系，与初始位姿无关。
- bias 更新：用一阶 Jacobian 近似 \(\Delta R(b_g + \delta b_g) \approx \Delta R(b_g) \cdot \text{Exp}(J_{\Delta R}^{b_g} \delta b_g)\)；bias 变化大时需要重新积分。
- 参考：Forster 的 IMU preintegration on manifold 论文。

#### Q6. 你评估了哪几种前端匹配算法？4D Radar 哪种最好？为什么经典 ICP/NDT 不行？

**参考答案要点**：考察 GICP/VGICP/NDT/Doppler-aided ICP 等的认知；4D Radar 通常 NDT/GICP 优于点对点 ICP（点稀疏，分布更稳）；近年文献也有用 Doppler 速度直接估自我运动 + scan match 残差混合的做法（如 4DRadarSLAM, ICRA'23）。

### B. 博世 3D LiDAR-IMU SLAM 实习（2023.05-2023.08）

#### Q7. Livox Mid360 与机械式雷达在点云结构上有何差异？这些差异如何影响去畸变实现？

**参考答案要点**：
- Mid360：非重复扫描，单帧花瓣形（rosette pattern），点的时间戳分布不像机械式那样按方位角线性递增；FoV 圆形 360°×59°；重复扫描密度低、累积扫描密度高。
- 去畸变：仍按 per-point 时间戳插值位姿，但**不能用方位角排序近似时间戳**——必须用 Livox 的 timestamp 字段；多帧累积时还要考虑非重复带来的稠密化。

#### Q8. 点云去畸变的常用做法？仅用 IMU 与用 SLAM 估计的位姿，区别？

**参考答案要点**：
- 思路：每个点用其时间戳处的位姿（相对帧起始时刻）反向变换到帧起始位姿。
- 仅 IMU：高频但有 bias 漂移，适合短时（一帧 100ms）；
- 用前端里程计：精度高但有延迟；
- 实践：通常用 IMU 做 inter-frame，里程计反推 bias，循环修正（如 LIO-SAM、FAST-LIO 的处理方式）。

#### Q9. 三面体（trihedral）标定深度相机+2D LiDAR 的几何原理？为什么不用棋盘 / 标定球？

**参考答案要点**：
- 几何：三面体三个互相垂直的面提供三个独立平面方程；2D LiDAR 切到三个面会得到三段直线，可解算三个平面在 LiDAR 系的方程；深度相机看到三个面则可直接拟合三个平面。三组平面对约束足以解 6 DoF 外参。
- 为什么选：2D LiDAR 是平面切片，棋盘格只能给出一条线（约束不足）；标定球对 2D LiDAR 给出一个点（更不够）。三面体提供 3 个非共面平面，对 2D LiDAR 也足够。
- 精度 ±1cm 怎么验证？追问 ground truth 来源。

#### Q10. 你说优化了前端里程计代码，具体优化了什么？性能 vs 精度？

**参考答案要点**：考察是否有具体的 profile / 算法替换 / 数据结构选择经验。如：用 KD-tree 替换 brute force、ikd-Tree、voxel grid 降采样、SSE/Eigen 向量化等。模糊回答减分。

### C. 迪伦 3D LiDAR SLAM 定位（2021.07-2022.07）

#### Q11. 600m × 500m 室内大场景下，定位 ±1cm 这个数字是怎么测出来的？参考真值是什么？

**参考答案要点**：考察工程严谨度。可信参考：全站仪/激光跟踪仪打点；事先 Mark 多个高精度控制点；或者基于精确预建图的回归。光说"±1cm"没有真值来源是不可信的。

#### Q12. 大场景下，先验地图是怎么管理的？回环 + 地图分块 + 关键帧密度策略？

**参考答案要点**：
- 大场景一般做分块（地图分 tile 加载）；
- 当前位置查询附近 tile 做 scan-to-map；
- 关键帧密度按位移+旋转双阈值；
- 回环用 ScanContext / 描述子或基于先验地图的全局重定位；
- 长走廊/重复纹理需要额外的人工地标（反光柱）。

#### Q13. 反光柱特征怎么从原始点云中识别？双雷达标定的目标函数是什么？

**参考答案要点**：
- 反光柱识别：高反射强度（intensity 阈值）+ 圆柱聚类（半径先验）+ 高度滤波；
- 双雷达标定：构造同一反光柱在两雷达坐标系下的对应点对，最小化 \(\sum \|R p_i^A + t - p_i^B\|^2\) → SVD 求解（Kabsch/Horn 算法）；地面约束可作为额外平面对应。
- 反光柱本身是点对点对应（强约束），地面是平面对应（约束 3 DoF：1 法向 + 2 旋转）。

#### Q14. 双激光雷达定位的融合：是雷达层融合（合并点云做一次 scan match）还是结果层融合？哪种更稳？

**参考答案要点**：
- 雷达层融合：标定准确时点云密度大、配准更稳；标定误差会进入每一帧；
- 结果层融合：每个雷达独立配准再融合（卡尔曼/加权），对单雷达失效更鲁棒；
- 实践常根据 FoV 重叠度、各自观测的几何完整度选择。考察是否有权衡思考。

## 二、SLAM 算法基础提问

> 候选人 SLAM 经验主要在硕士+博世+迪伦阶段（2021-2023），过去 2 年偏感知，需要验证基础是否还在。

#### Q18. 简述 SLAM 的状态量、运动模型、观测模型；EKF SLAM 与基于图优化的 SLAM 在数学形式上的本质差异？

**参考答案要点**：
- 状态：位姿 + 路标（+IMU 状态量 vel/bias）；
- 运动模型 \(x_k = f(x_{k-1}, u_k) + w_k\)；观测 \(z_k = h(x_k, m) + v_k\)；
- EKF：递推线性化、保留一阶矩；marginalize 历史状态；
- 图优化（factor graph）：保留全部历史状态做 batch / 滑窗 BA，迭代重新线性化，精度更高；
- 区别：是否多次重新线性化、是否保留全历史。

#### Q19. 边缘化（marginalization）的数学过程？什么是 First Estimate Jacobian (FEJ)？为什么需要 FEJ？

**参考答案要点**：
- Marginalization：用 Schur complement 把要丢的状态在信息矩阵中消掉，剩余状态获得一个先验因子；
- FEJ：被 marg 状态相关的雅可比固定在第一次线性化点（first estimate），不再随当前估计变化；
- 为什么：避免不同状态的雅可比在不同线性化点导致的 inconsistency（系统观测到不存在的方向→零空间被破坏，导致系统的可观性丢失，引入虚假信息）；OKVIS、VINS-Mono 的 sliding window 都用 FEJ。

#### Q20. ICP / NDT / GICP 的核心区别？分别的代价函数？

**参考答案要点**：
- 点对点 ICP：\(\min \sum \|R p_i + t - q_i\|^2\)，对噪声敏感；
- 点对面 ICP：\(\min \sum (n_i^T (R p_i + t - q_i))^2\)，平面假设下更鲁棒；
- NDT：把目标点云体素化建高斯分布，最大化源点云在分布上的似然；离散化便于 GPU；
- GICP：点对点 + 各自的局部协方差，最小化 \(d_i^T (C_q + R C_p R^T)^{-1} d_i\)，本质是分布对分布。

#### Q21. IMU 预积分相比直接积分的核心收益？bias 变化时怎么避免重新积分？

**参考答案要点**：见 Q5。补充：bias 变化超过阈值（如 0.001 rad/s）就重积分。

#### Q22. 闭环检测的常见方法？误闭环（false loop）后如何在图优化里恢复？

**参考答案要点**：
- 方法：BoW（DBoW2/3）、ScanContext（LiDAR）、NetVLAD（学习类）、几何 ICP 验证；
- 误闭环防御：几何验证（RANSAC + ICP 残差阈值）、时序约束、Switchable Constraints / DCS（动态调整因子权重）；
- 恢复：误闭环边权重置 0 或通过 robust kernel（Cauchy/Huber）压制。

#### Q23. Pose Graph Optimization 与 Bundle Adjustment 的区别？什么时候只能用 PGO？

**参考答案要点**：
- BA：联合优化位姿+地图点，重投影误差，O(N×M) 规模大；
- PGO：只优化位姿，节点间约束是相对位姿，规模小、收敛快；
- 何时只用 PGO：地图点不可观（如 LiDAR 直接给点云做配准残差），或用于全局闭环修正后用 BA 局部 refine（hierarchical 思路）。

#### Q24. 多传感器（IMU + LiDAR + Camera）的融合方式有哪些？松耦合 vs 紧耦合？

**参考答案要点**：
- 松耦合：每个传感器独立估计 → EKF/PGO 融合最终结果（如 GPS+IMU EKF）；
- 紧耦合：原始观测进入同一优化目标（残差合并），如 LIO-SAM、FAST-LIO2、VINS-Fusion；精度高但维护成本高。

#### Q25. 卡尔曼滤波 vs 优化方法在 SLAM 中的取舍？什么场景下你会选 EKF/iEKF？

**参考答案要点**：
- 算力受限/实时要求高 → EKF/iEKF（FAST-LIO2 用 iEKF）；
- 对精度要求高、可离线/算力宽裕 → 滑窗 BA / 全局 BA；
- iEKF 通过迭代线性化逼近优化的精度但保留滤波的稀疏更新效率。

#### Q26. 仿真岗位相关：你会怎么搭建一个 SLAM 算法的离线仿真评测？

**参考答案要点**（重点考察岗位匹配度）：
- 数据：开源数据集（KITTI/NCLT/MulRan/HILTI）+ 自采 + 仿真器（CARLA/AirSim/Gazebo+IMU 噪声模型）；
- 指标：ATE / RPE（绝对/相对位姿误差）、回环检测 P/R、CPU/GPU 占用；
- 工具：evo、g2o_viewer、rerun.io；
- 故障注入：传感器丢帧/外参扰动/动态目标比例 → 测鲁棒性。

## 三、C++ 编程能力考核（语法）

> 候选人简历写"精通 C++"，考察 C++11/14/17 现代特性 + 内存/并发常识。

#### Q27. `unique_ptr`、`shared_ptr`、`weak_ptr` 的语义区别？什么时候必须用 `weak_ptr`？

**参考答案要点**：
- `unique_ptr`：独占所有权，不可拷贝、可移动，零开销；
- `shared_ptr`：引用计数，控制块带强引用+弱引用计数，拷贝原子++；
- `weak_ptr`：观察者，不增加引用计数，用 `lock()` 提升为 `shared_ptr`；
- 必须用 `weak_ptr`：打破 `shared_ptr` 循环引用（如父子节点互引、Observer 模式）。

#### Q28. `std::move` 实际做了什么？右值引用、移动构造的语义？

**参考答案要点**：
- `std::move` 只是 `static_cast<T&&>`，不动任何东西，把左值"标记"为右值引用；
- 真正"移动"取决于类的移动构造/赋值是否实现；
- 对于无显式移动构造的类（含资源），fall back 到拷贝；
- 移动后原对象处于"valid but unspecified" 状态，析构合法。

#### Q29. 写一个类，使其满足 RAII 并支持移动语义、不可拷贝（让候选人现场写）

**参考答案**：

```cpp
class FileHandle {
public:
    explicit FileHandle(const char* path) : fp_(std::fopen(path, "rb")) {}
    ~FileHandle() { if (fp_) std::fclose(fp_); }

    FileHandle(const FileHandle&) = delete;
    FileHandle& operator=(const FileHandle&) = delete;

    FileHandle(FileHandle&& other) noexcept : fp_(other.fp_) { other.fp_ = nullptr; }
    FileHandle& operator=(FileHandle&& other) noexcept {
        if (this != &other) {
            if (fp_) std::fclose(fp_);
            fp_ = other.fp_;
            other.fp_ = nullptr;
        }
        return *this;
    }

    FILE* get() const { return fp_; }
private:
    FILE* fp_ = nullptr;
};
```

**考点**：移动构造/赋值都要 `noexcept`（vector 扩容时才走 move 而不是 copy）、自赋值检查、析构 nullptr 防御、Rule of Five。

#### Q30. 虚函数底层怎么实现？为什么基类析构要写 virtual？

**参考答案要点**：
- vptr + vtable，每个有虚函数的类有一份 vtable，对象首部有 vptr；
- 基类析构非 virtual 时，`delete base_ptr` 只调基类析构，子类资源泄漏；
- 但若子类没新增需要析构的资源，virtual 析构有性能开销；
- 现代实践：作为多态基类必须 virtual ~Base()，否则 final 或非多态。

#### Q31. `const T&` vs `T&&` vs `T` 作为函数参数的取舍？什么是「完美转发」？

**参考答案要点**：
- `const T&`：只读，不复制；
- `T`：拷贝（小对象/想取所有权时）；
- `T&&`（万能引用，模板里）：可同时绑左值/右值；
- 完美转发：模板中 `template<typename T> void f(T&& x)` + `std::forward<T>(x)` 保留值类别向下传递。

#### Q32. `std::vector` 扩容时为什么要求 move 构造 noexcept？不 noexcept 会怎样？

**参考答案要点**：
- vector 提供 strong exception guarantee：扩容失败时容器状态不变；
- 如果 move 构造可能抛异常，搬一半失败无法回滚（旧元素已被 move），所以会 fallback 到 copy；
- 因此自定义类型应当 `noexcept` move ctor / move assign。

#### Q33. lambda 捕获方式：`[=]`, `[&]`, `[this]`, `[*this]`, 默认 mutable？哪种容易出错？

**参考答案要点**：
- `[=]`：值捕获（拷贝）；
- `[&]`：引用捕获；
- `[this]`：捕获 this 指针，对象析构后 lambda 调用是 UB；
- `[*this]`（C++17）：捕获 *this 的拷贝（lifetime 安全）；
- 默认非 mutable，值捕获在 lambda 体内是 const；
- 易错：异步任务里捕 `[&]` 或 `[this]`，原对象先析构，lambda 执行时悬空。

#### Q34. `std::map` vs `std::unordered_map` 的复杂度、迭代器失效、典型选择？

**参考答案要点**：
- `map`：红黑树，O(log n)，按 key 有序，迭代稳定；
- `unordered_map`：哈希，平均 O(1)/最差 O(n)，rehash 时迭代器失效（指针/引用仍有效，C++17）；
- 选择：需要顺序遍历选 map，单纯查找选 unordered_map；自定义 key 需要哈希函数 + equal_to。

#### Q35. `std::mutex` + `std::lock_guard` / `std::unique_lock` / `std::scoped_lock` 区别？多锁如何避免死锁？

**参考答案要点**：
- `lock_guard`：构造加锁、析构解锁，不可手动解锁；
- `unique_lock`：可移动、可手动 unlock/lock、配 condition_variable 用；
- `scoped_lock`（C++17）：一次锁多把锁，内部用 deadlock-avoid 算法（std::lock）。
- 避免死锁：固定加锁顺序、尽量缩小临界区、用 `std::lock` / `scoped_lock`。

#### Q36. `std::condition_variable` 为什么要配合 `unique_lock`？为什么 `wait` 需要 predicate？

**参考答案要点**：
- 必须可手动 unlock，所以 lock_guard 不行；
- predicate 防止"虚假唤醒"（spurious wakeup）：内部循环 `while(!pred()) wait(lock);`；
- 不带 predicate 容易在条件未真时被错误唤醒。

#### Q37. Eigen 在类成员里有 fixed-size 矩阵（如 `Eigen::Matrix4d`），new 出来的对象崩溃，为什么？怎么修？

**参考答案要点**：
- Fixed-size Eigen 类型要求 16 字节对齐（SSE/AVX）；
- new 默认按 alignof(max_align_t)（一般 8 或 16）但 std::vector 等容器分配器不一定满足；
- 修复：(1) 类内加 `EIGEN_MAKE_ALIGNED_OPERATOR_NEW`；(2) 容器用 `Eigen::aligned_allocator<T>`；(3) C++17 后开启 `-faligned-new`/`__STDCPP_DEFAULT_NEW_ALIGNMENT__` 时部分情况自动对齐；(4) 用 dynamic-size（如 `Eigen::MatrixXd`）规避。

#### Q38. 看代码，指出问题：

```cpp
std::vector<int> v = {1, 2, 3, 4, 5};
for (auto it = v.begin(); it != v.end(); ++it) {
    if (*it % 2 == 0) {
        v.erase(it);
    }
}
```

**参考答案要点**：
- `erase` 后 `it` 失效，`++it` 是 UB；
- 修复：`it = v.erase(it);` 在偶数分支里，奇数分支 `++it`；或用 `std::erase_if`（C++20）/ `std::remove_if + erase` 习语。

#### Q39. 看代码，指出 bug：

```cpp
class Worker {
    std::thread t_;
public:
    Worker() { t_ = std::thread([this] { run(); }); }
    void run() { /* ... */ }
};
```

**参考答案要点**：
- 析构里没有 `t_.join()` 或 `detach()` → `std::thread` 析构时若 joinable 会 `std::terminate`；
- 同时 lambda 捕 `this`，对象析构后线程仍在跑会访问悬空对象（UB）；
- 修复：析构里 join；并保证退出标志通知线程；或者把 `this` 用 `shared_ptr<Worker>` + `std::enable_shared_from_this`。

#### Q40. `constexpr` vs `const` vs `inline` 变量？什么是 `if constexpr`？

**参考答案要点**：
- `const`：运行时常量（不可改），可由运行时初值；
- `constexpr`：编译期常量，要求初值在编译期可求；
- C++17 `inline` 变量解决头文件多 TU 重复定义；
- `if constexpr`：编译期分支，未匹配分支不 instantiate（用于模板特化简化）。

#### Q41. 判断下面代码会编译/运行的结果：

```cpp
int x = 10;
auto f = [x]() mutable { x++; std::cout << x << " "; };
f(); f(); std::cout << x;
```

**参考答案要点**：输出 `11 12 10`。lambda 内 `x` 是值捕获的副本，mutable 允许修改副本，外部 `x` 不变。
