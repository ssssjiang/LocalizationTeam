# 边界处理——导航 梳理稿

**来源**：`边界处理——导航_20260608_105452.md`（导航模块技术设计文档，对应上游 PDD：AI自主找边）

---

## 核心结论

导航对边界的处理分两个阶段：**建图**（识别并确定边界类型）和**割草**（按边界类型决定沿边轨迹策略）。沿边核心逻辑是**标准模式严格跟线、智能模式可外扩贴边**，危险边界统一取最内侧并内缩。用户侧仅暴露安全/危险两级，导航内部细分三类。

---

## 一、导航上游数据

### 定位数据（5 种类型）

| 定位类型 | 可靠性 | 使用场景 |
| --- | --- | --- |
| ODO | 低 | RTK 产品夜间退桩/上桩 |
| RTK | 高（存在假固定解） | RTK 固定解场景 |
| VSLAM | 高 | RTK 产品有 VSLAM 地图场景 |
| VIO | 中 | RTK 产品退桩/上桩、RTK 非固定解 |
| LIO | 高 | 雷达产品 |

注意事项：
- 假固定解对导航无感，且随机不稳定，需后续割草过程中检测修复
- VIO 带局部地图可做当前位置前 200s 的位姿修正
- VSLAM 可用于优化建图轨迹（待定：分段还是全局）

### 感知数据（三级边界分类）

感知提供三级类型 → 导航向状态机/插件反馈**一级**类型（安全/危险）。

| 一级 | 二级 | 三级 | 风险说明 |
| --- | --- | --- | --- |
| 安全边界 | 高度边界 | 实心 | 可开打草头 |
|   |   | 镂空 | 防卡住 |
|   |   | 网状 |   |
|   |   | 植被 | 防破坏植被 |
|   | 齐平边界 | 可跨 | 可跨骑割草 |
|   |   | 不可跨 | 鹅卵石等开刀盘危险 |
|   | 默认边界 | 未知边界 |   |
| 危险边界 | 跌落边界 | 跌落 | 易跌落 |
|   | 水池边界 | 水池 | 落水 |
|   | 易陷边界 | 泥沙 | 陷入无法脱困 |

## 二、建图状态

### 不贴边处理

- 建图过程中，导航根据实时检测的边界类型给出**边界引导线**
- 保存地图时，给出 AI 检测的实际边界路径建议（需 RGB 平面真实地图就绪后）
- 手遥修改边界（方案制定与评估中）；割草阶段检测边界修改（后续加入）

### 定位不准处理

- **VIO 定位**：建图降速至 0.2m/s（可用 VSLAM 优化建图轨迹）
- **假固定解**：导航无法判断，需在后续割草过程中检测并修复地图

### 边界类型确定原则

- 用户侧：只能设置危险边界（不能设置安全边界）
- 导航内部：安全边界（含齐平）/ 默认边界 / 危险边界（高低落差大 + 水池）
- 建图中导航自行保存检测结果；用户确认后覆盖 AI 检测类型

### 地图学习

- 手遥充电桩通道（当前），后续扩展区域间通道
- RTK 阴影区：割草过程中偷建 VSLAM 地图，或提示用户在该区域走弓字建图

## 三、割草/沿边策略

> 沿边需同时结合：实时定位类型 + 手遥边界 + AI 检测边界类型

用户逻辑：
- 用户确认**危险边界** → 沿边内缩
- 用户不确认/确认**安全边界** → 导航判断是否为齐平边界；是则取消内缩 5cm；不是则保持现有沿边方式

### 标准模式

- 定位好时严格按建图轨迹走
- 危险边界和其他边界：实时监测边界与建图边界取**最小集（最内侧）**
- 轨迹**不内缩**

RTK 产品 VIO 阶段（最大误差约 0.4m/20m）的处理：
1. 最多探索 10m
2. 全程 VIO → 记录轨迹 traj1 和最远点 state1
3. 退回至上一个 RTK 信号好的点，封死路径 traj1
4. 重新规划至 state1 附近 RTK 好的点，继续跟线

### 智能模式

- 定位好时：安全/其他边界最多可外扩 **0.3m**
- 安全边界：实时检测边界与建图边界取**最大集（最外侧）**
- 默认边界：不内缩
- RTK 信号不好时：同标准模式

---

## 与 PDD（AI自主贴边）的对应关系

| PDD 沿边策略 | 导航文档对应逻辑 |
| --- | --- |
| 安全边界 + AI 识别向外 → 取最大集、不内缩 | 智能模式：取最外侧，外扩最多 0.3m |
| 危险边界 → 取最小集、内缩 10cm | 标准/智能模式：取最内侧；内缩由状态机执行 |
| 无属性边界 → 沿手摇轨迹 | 默认边界：不内缩，按建图轨迹 |
