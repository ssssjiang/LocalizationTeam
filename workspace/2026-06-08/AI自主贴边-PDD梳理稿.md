#  原始需求（RR）

RR （Raw Requirement），来自公司内、外部客户的、解决方案伙伴的、关于公司产品与解决方案的、以客户视角描述的原始问题或者原始诉求。

原始需求细分为两类场景：

- 1）销售项目需求：在市场销售项目售前、售后各阶段（对应LTC流程ML/MO/MCE阶段）产生的，并与项目的销售和交付直接相关的需求；
- 2）非销售项目需求：泛指拜访客户、市场交流研讨活动，以及与解决方案伙伴合作过程中所得，与具体的销售项目无直接关联的需求，以及交付实体间提出的内部需求（如：解决方案对部件产品、产品对产品、产品对平台提出的需求）。

从用户角度的痛点，想要什么？

本需求为非销售项目内部产品需求，来自产品团队对割草机用户痛点的调研与功能迭代规划，原始用户视角的诉求如下：

| 需求编号 | 需求名称 | 核心用户痛点 |
| --- | --- | --- |
| RR-01 | 边界识别 | 未识别或新增的危险边界导致机器卡困、剐蹭、翻车甚至损坏。 |
| **RR-02** | **精确边缘割草** | **现有边割因安全距离存在 3-5cm 漏割，用户期望更完整的割草，尤其是跨骑割草。** |
| **RR-03** | **手动建图优化** | **用户遥控建图难以走直线和精准贴边，导致边界不准，沿边割草可能不够贴边。** |
| RR-04 | 禁区管理优化 | 手动建立禁区繁琐且不准确，禁区比边界变化更频繁，希望有智能快速的方案。 |

| RR-06 | 完全自主建图 | 现有自主建图启动和完成条件严苛，用户体验差，希望实现开箱即用的自主建图能力。 |

# 系统需求(SR)

SR （Svstem Requirement），为支撑“初始需求（IR）”所需要支持的具体需求。是站在研发视角，描述系统对外呈现的、可测试的全部功能需求和非功能需求。

- 其中功能需求是对系统提供的功能的场景化的具体要求，
- 非功能需求是对系统的成本、全局质量属性（主要是DFX）、技术限制等非功能性方面的具体要求。

### 边缘属性分类（P0-P1）

系统需要在所有捕捉到的边缘进行语义判断。场景汇总如下：

1. 高度边缘（垂直凸起型边界）

核心定义

与草坪平面存在 **≥5cm 的垂直高度差 **，具备明显物理凸起结构，割草机机身 / 刀盘无法正常跨越，属于不可逾越的刚性 / 半刚性边界，既是草坪作业的核心安全边界，也是核心作业边界，边界辨识度整体较高，核心难点为遮挡、光影、异形结构带来的识别误差。

1. 平齐边缘（平面过渡型边界）

核心定义

与草坪平面的高度差≤2cm，无明显垂直凸起 / 凹陷，边界两侧处于同一水平面，两侧水平面至少沿交接线能够向两侧外扩15cm。通过材质、颜色、纹理、植被类型区分草坪与非草坪区域，割草机可平稳驶过，无安全跨越风险，但直接决定割草作业的完整性与精准度，是AI 找边的核心精度场景，核心难点为边界过渡模糊、材质 / 植被特征接近导致的误判。

1. 低矮边缘（向下凹陷坠落风险型边界）

核心定义

## 边界场景（Corner Case）处理逻辑

| 场景 | 处理逻辑 |
| --- | --- |
| 光照突变（树荫到强光、逆光） | 系统自动调整摄像头 HDR 参数，增强图像的动态范围，同时结合多帧数据融合，避免光照变化导致的边界误判 |
| 树荫阴影干扰 | 结合深度信息与语义分割模型，区分阴影区域与真实的非草坪区域，避免将阴影误判为非草坪边界 |
| 模糊过渡边界（草坪与泥土 / 沙地的过渡带） | 通过多帧的连续识别，结合历史边界数据，判断真实的草坪边界，避免将过渡带误判为边界 |

1. 融合双目点云、语义分割算法、BEV 鸟瞰图算法，对环境进行多类别语义分割，精准区分草坪、花坛、步道、沙地等非草坪区域；
2. 顶配版额外融合激光雷达的点云数据，提升深度信息的准确性，进一步提升边界识别的精度；
3. 基于分段式的边界识别结果，构建完整的草坪边界地图，解决原纯点云找边效果差的问题，提升自主建图的准确性。

### 禁区边界优化场景 AI 找边扩展

将 AI 找边能力扩展到语义地图与禁区管理场景：

1. 用户自定义禁区边界优化：在每次作业过程中，实时识别禁区的真实边界，对比用户原设置的禁区边界，当发现存在偏差且识别置信度较高时，向用户给出禁区边界的优化建议；
2. 新禁区建议：当系统识别到新的障碍物区域时，进行连续 3 次作业的确认，若该障碍物区域持续存在，且识别置信度≥90%，则向用户建议将该区域标记为禁区，用户可一键确认。
