## 0. 结论先行

- **三个纯视觉竞品在 VSLAM 能力上明显分三派**：
  - **Terramow**：能力激进——支持自主建图、实时建图、不限多区域、长通道；**异常处理依 IMU 抬起信号分支**（"搬"出地图会一直重定位 5min 不报错——违规，"推 / 拉"出地图会报"无法执行任务"）。
  - **Mova-viax300**：能力保守——只手动建图、最多 3 个区域、无割草建图；**异常处理一致**（出错就退桩 / 报错）。
  - **YUKA Mini Vision**：折中路线——抱起后**地图内不转圈直接重定位**；搬到无共视区会**主动行走 3m 自转后报出界**（介于 Terramow 5min 瞎走 vs Mova 原地报错之间）；**回桩用红外识别桩标记，不依赖 SLAM 重定位**（与另两家路线根本不同）。
- **共同短板**：换桩（APP 不操作）后**区域跟着桩平移**、机器实际位置与 APP 显示不一致 —— **三家都没做对**（YUKA / Mova / Terramow 全部踩坑）。
- **行为分支维度的差异**：
  - **Terramow** 按 IMU 抬起信号分"推 / 拉 / 搬"三支；
  - **YUKA** 按搬动过程中相机是否更新定位分两支（实时更新 → 立即报错；未更新 → 走特定流程重定位）；
  - **Mova** 不分支，行为一致。
- **Eden 设计可以打的差异点**：
  1. 搬动后**回原始位**的策略（Mova 回起始位，Terramow / YUKA 从重定位位置继续，Eden 之前希望回原位）
  2. APP 支持换桩（三家都没做对）
  3. 与老地图持续关联（避免出界——三家都因此出过错）
  4. 区域上限不限 + 通道支持长度对齐 Terramow（60m）
  5. 雨淋场景兜底（两家测试结论均未填，YUKA 五一未测）
  6. **是否引入红外/二维码等专用桩标记替代 SLAM 重定位回桩**（YUKA 路线，硬件成本+1，但可靠性高）

### 2.3 边界 / 多区类异常

#### 2.3.1 搬动方式分类（不同竞品按不同维度分支）

> **关键观察**：竞品行为按搬动方式分支，但**分支维度不一样**：
>
> - Terramow：按 **IMU 抬起信号**分"推 / 拉 / 搬"
> - YUKA：按**搬动过程中相机是否更新定位**分两支
> - Mova：不分支，行为一致

**Terramow 分支**（按 IMU 抬起信号）：


| 搬动方式             | IMU 信号    | Terramow 行为分支                                       |
| ---------------- | --------- | --------------------------------------------------- |
| **推**（连续移动，无抬起）  | 不触发       | **不重定位**，在新位置当作连续轨迹继续建图 / 工作 `[xlsx R8.1]`          |
| **拉**（缓慢拖动，无抬起）  | 不触发 / 弱信号 | 重定位 → 警告"不在已建图工作区域，无法执行任务" `[xlsx R3.1]`            |
| **搬**（瞬间移动，触发抬起） | 触发抬起警告    | 报抬起 → 解除后 → 在新位置一直重定位（5min 不停）`[xlsx R8.2 / R10.2]` |


**YUKA 分支**（按相机是否更新定位）：


| 搬动过程中相机状态               | YUKA 行为分支                                                                      |

### 2.5 IMU 故障类（待验证）`[全部 1月]`

- Terramow 疑似用 **TDK IMU**（与 360 同款，非高端）。
- 8081 / 7081 一小时漂移可能就到 1°（李岩反馈）。
- 主要风险不是 BIAS 而是 **ACC 噪声 / MCU 抖动出异常值**。
- 加热补偿可考虑（板上加电阻预热到 CPU 稳定温度后再开机）。
- 共识：只要 BIAS 不大、转 360° 误差不超过 ±10°，VIO 跑得好就够，不需要为 7081 付高额成本。
