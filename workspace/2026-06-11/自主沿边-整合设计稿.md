## 2. 边界类型体系（统一口径）

> 三套体系容易混。落到执行只有一条链路：**感知给三级 → 导航滤成内部三类 → 对用户只暴露两级**。

### 2.1 三层映射

| 用户侧（可见可编辑） | 导航内部（执行用） | 感知三级（输入） | 一期是否聚焦 |
|---|---|---|---|
| **危险边界**（用户只能标这个） | 危险边界 | 跌落 / 水池 / 易陷(泥沙) | ✅ 跌落 + 水池 |
| **常规/安全**（用户不可标，机内定） | 安全边界（仅齐平） | 齐平-可跨 | ✅ 齐平可跨 |
| 同上 | 默认/其他边界 | 高度(实心/镂空/网状/植被)、未知 | ⚠️ 高度非核心 |

要点：

- 用户**只能标危险边界**，安全/默认全部由导航算法内部标注 `[确认 5.20]`
- 一级（安全/危险）只给用户看；**算法实际从二级（齐平/水池/跌落）取策略** `[确认]`
- 本期算法只稳定关注 **齐平(可跨) + 水池 + 跌落**；高度边界非核心、电线排除、**禁区边界不做且以后也不 AI** `[确认 6/1 丛一鸣]`

### 2.3 AI 贴边作用范围：草坪外轮廓 vs 禁区边界 `[确认 6/1]`

> 「禁区边界不做且以后也不 AI」常被误读，单独拍清。

地图里有两类边界，AI 自主贴边只作用于前者：

| 边界 | 含义 | 是否走 AI 贴边 |
|---|---|---|
| **草坪外轮廓边界** | 草坪外缘（墙/路沿/水边/跌落等），要尽量贴边割干净 | ✅ AI 贴边的作用对象 |
| **禁区边界** | 用户在草坪内部圈出的不割区域（花坛/水井/障碍群），机器要绕开 | ❌ **一期不做，长期也不做** |

理由（丛一鸣）：**禁区本质属于危险/避让区，不能让 AI 去"贴近"它**（贴近 = 增加闯入风险）。所以禁区只保留"避让"，不做"贴边优化"；6/22 禁区贴边程度仍走老逻辑，不走 AI。

### 2.2 危险边界检测分工

- 齐平 / 高墙 / 水池：感知检测较稳 `[确认]`
- **跌落边界：由导航负责检测**（非感知） `[确认 导航稿]`

## 3. 子部分一+二：建图阶段的边界处理与交互

> 一期所有「新增用户交互」**集中在建图完成后这一个环节**。建图过程中只有展示性引导线，割草阶段无交互。

### 3.1 建图过程中 `[确认 一期]`

- 导航按实时检测的边界类型给**边界引导线**（展示性，用户不可在此改类型）
- 保存地图时给出 AI 检测的实际边界路径建议（依赖 RGB 平面真实地图就绪）
- **建图过程中不做边界类型确认 UI**（5.20：3-1-1 实时标类型 UI 一期不上）`[确认]`
- 思羽期望的「遥控建图过程中直接标危险边界起/终点」→ **延后** `[确认 一期不做]`

### 3.2 建图完成后 `[确认 一期核心]`

唯一的用户交互流程：

```
建图完成
  → 有危险边界：提示「已发现潜在危险边缘，请确认」→ 进确认页
                确认页：AI 检出危险段预标红/闪烁，点击后取消闪烁
                用户可：删除误检段 / 拖端点调整 / 主动新增危险段
                点 Save 持久化（不 check 直接 Save 也会保存 AI 检出结果）
  → 无危险边界：直接进「地图管理」
```

约束：

- 仅允许修改/新增**危险边界**；安全边界用户不可设 `[确认]`
- 仅**真实草坪外轮廓**可改类型；分割子区域内部边界**不可改** `[确认 5.20]`
- 用户编辑危险段**不可跨子区域**；选中区域高亮、其余置灰 `[确认 5.20]`
- 危险边界在全地图视图（首页等）展示 `[确认 5.20]`
- 用户标危险 + 感知结果 → **取并集**，且割草中实时感知危险仍生效 `[确认]`
- 区域合并后危险边界 → **倾向截断**，未最终拍板 `[未定]`
- 用户主动加危险边界的**默认段长**（2m？）→ **未定** `[未定]`

| 维度 | 手遥建图 | 完全自主建图 |

## 4. 子部分三：割草 / 沿边阶段的策略

### 4.1 沿边模式 — 定义与适用 `[确认]`

| 模式 | 一期定位 | 核心特征 |
|---|---|---|
| **标准模式** | ✅ **默认**（5.20 决定从智能改回标准，与宇阳同步） | 定位好时严格按建图轨迹走，不外扩 |
| **智能模式** | 标 beta/lab，默认不开 | 允许在安全/默认边界上越过建图轨迹外扩贴边（≤0.3m）；RTK 信号差时退回标准 |

> 两模式下各类边界的**具体取法/内缩外扩**见 §4.2 交叉矩阵。

适用范围：

- 每块草坪可单独设标准/智能（割草偏好）`[确认 5.20]`。
- ⚠️ `[过时]` 提醒：PDD 梳理稿写「所有自主沿边策略均为沿边模式下-'智能模式'应用」（PDD V0.1, 5/07）。**5.20 会议已推翻**，一期默认 = 标准模式，智能模式降级为 beta。读 PDD 时此处以会议为准。

### 4.2 边界类型 × 模式 — 交叉矩阵 `[确认]`

> **一句话结论**：模式（标准/智能）只对**安全边界、默认边界**起作用；对**危险边界两种模式完全一致**——永远取最内侧、额外内缩，模式不会放松危险边界。

先统一两个术语：

- **最小集（最内侧）**：实时感知边界与建图边界，取更靠草坪内侧的那条 → 离边界更远、更保守。
- **最大集（最外侧）**：取更靠外的那条 → 贴边更紧、割得更完整。

| 边界类型（用户属性 / 内部） | 标准模式（一期默认） | 智能模式（beta，默认不开） | 模式间是否有别 |
|---|---|---|---|
| **危险边界** | 取**最小集（最内侧）**，**内缩 ≥10cm** | **与标准完全相同**：取最小集，内缩 ≥10cm；**不参与外扩** | ❌ **无区别** |
| **安全边界（=齐平 可跨）** | 沿建图轨迹贴边，**去掉现有 5cm 内缩**，不外扩 | 取**最大集（最外侧）**，最多**外扩 0.3m**（比建图轨迹更贴边） | ✅ 有区别 |
| **默认 / 其他边界** | **内缩 5cm**（保持现状）`[未定]` | **不内缩**，可外扩最多 0.3m | ✅ 有区别 |

关键补充：

- **危险内缩量**：基线 10cm，可能到 20cm/半机身，上限 `[未定]`（待摸）。
- **智能模式失效条件**：RTK 信号差 / 定位不好时，智能模式**退回标准模式**，外扩能力作废 `[确认]`。
- **默认边界内缩量口径冲突**：导航稿写「默认边界不内缩」，但 5/19、5/20 流程图写「内缩 5cm」，需向李欢澄清（00 总纲 M8）`[未定]`。
- 直观理解：智能模式 = 在「安全/默认」边界上允许机器越过建图轨迹去贴真实边缘（最多 0.3m），换更完整的割草；危险边界不给这个权限，安全永远优先。

### 4.3 实时感知融合：危险等级取高 `[确认]`

- 建图边界 + 用户修改 + 沿边实时感知 → **按危险等级取高（优先危险）**
- 「或关系」是早期表述，已统一为**取危险等级更高者** `[确认 5.20 D7]`
- 割草中实时感知危险 > 建图轮廓安全 → **导航立即按更危险侧执行，无需用户实时确认** `[确认]`

### 4.4 VIO 限距（RTK 产品定位退化兜底）`[本期不上]`

> ⚠️ **本期不做**（6/11 宋姝确认）。下方为方案存档，留待后续排期。

方案（存档）：基于现有 20m 最大误差 0.4m：① 最多探索 10m → ② 全程 VIO 则记录 traj1 与最远点 state1 → ③ 退回上一个 RTK 信号好的点、封死 traj1 → ④ 重新规划至 state1 附近 RTK 好点继续跟线。产品是否接受折返行为 `[未定]`。

## 5. 感知识别 → 处理全链路

### 5.1 建图链路 `[确认]`

```
感知实时检出（稳定类型：齐平/水池/跌落主优先级）
  → 导航滤波后定边界类型，稳定类型自动写入地图属性（即使用户不确认也生效）
  → 建图完成 → §3.2 用户确认页（增删危险段）→ Save 持久化
```

### 5.2 割草链路 `[确认]`

```
割草中感知实时检测
  → 取「建图保存的边界结果 + 实时感知结果」按危险等级取高
  → 导航即时按更危险侧执行避让/内缩
  → 割草时的识别结果只用于当次策略，不累积保存（不回写地图）  [确认 6/11 宋姝]
```

数据写入边界（关键原则）`[确认 6/11 宋姝]`：

- **只有建图阶段会保存边界**（感知识别 + 用户添加危险边界 → 写入地图）。
- **割草阶段不累积、不回写**：割草中实时感知的新危险边界只参与当次策略，任务结束即丢弃，下次割草仍以建图保存结果为基线。
- 推论：因为割草识别结果不入库，**割草阶段不存在「让用户确认新边界」的环节**（既不在割草中、也不在割草结束后）。新边界要进地图，须走下一次建图/边界编辑流程。

## 7. 设计空白与待确认 — 回答宋姝四问

### Q1 — 建图 & 沿边的新增交互，分开还是统一？

`[确认]` **设计上是分开的，且交互高度集中**：

- 用户的边界类型增删/确认交互 = **只在建图完成后这一个环节**（§3.2）

→ 即：交互不是「建图一套、沿边一套」，而是**全部前置到建图完成后**，沿边阶段零交互。

### Q2 — 自主建图 vs 手遥建图，设计有差异吗？

`[空白]`（核心疑点）：

- 当前 confirmed 的边界类型/交互设计**全部围绕手遥建图**（建图完成后改类型）
- 完全自主建图只在 PDD 找边算法层有描述（多传感器融合 + 「对模糊/危险边界触发用户确认」），但**该确认是过程中弹窗还是建图后统一、与手遥是否同一套 UI，设计与会议都没写**

### Q3 — 感知识别到后的处理？

- 建图阶段链路 `[确认]`：感知检出 → 导航滤波定类型 → 稳定类型自动写图 → 建图后用户确认页增删 → Save（§5.1）。**边界只在建图阶段保存**。
- 割草阶段 `[确认]`：取「建图保存结果 + 实时感知」危险等级取高、导航即时执行；**割草识别结果不累积、不回写地图** `[确认 6/11 宋姝]`
- `[空白]`：感知→导航→插件的**上报协议/接口细节**原文未描述（仅此项仍空白）

### Q4 — 导航对危险边界的处理时机 / 是否要用户确认？（最关键）

| 场景 | 设计答案 |
|---|---|
| 建图过程中识别到危险边界，及时处理还是等保存？ | `[确认]` 导航**实时检测+给引导线**；但**「定类型 + 用户确认」统一放到建图完成后**，一期不在过程中做类型确认交互。稳定检出的危险类型会自动写图，用户的增删确认在保存环节。 |
| 手遥沿边时新识别危险 | `[确认]` 用户在控制，导航即时按更危险侧执行即可，相对简单。 |
| **自主沿边（割草）时新识别危险边界，导航怎么处理？** | `[确认]` 当次**即时按更危险侧避让/内缩，无需用户实时确认**。 |
| **该新危险边界是否需要用户确认？割草中确认还是割草结束后确认？是否入库？** | `[确认 6/11 宋姝]` **不入库、不累积、不回写地图**：割草识别结果只用于当次策略，任务结束即丢弃。因此**不需要用户确认**（既不在割草中、也不在割草结束后）；新边界要进地图须走下一次建图/边界编辑（§5.2）。 |

> 补充：PDD 数据闭环（用户忽略/低置信确认 → 上传点云）和禁区逻辑（新障碍连续 3 次作业 → 建议禁区、用户一键确认）是**数据采集/禁区**链路，与「沿边边界是否回写地图」是两回事，不冲突。
