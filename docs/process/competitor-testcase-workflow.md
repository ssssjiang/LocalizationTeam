# 竞品测试用例整理工作流

> 沉淀自：2026-06-08 Mova ViAX 300 纯双目割草机测试用例整理过程
> 适用场景：针对某款竞品整理一套完整、可执行、可回填的测试用例文档

---

## 1. 工作流总览

```
Step 1  源材料全读
Step 2  竞品官方规格核查
Step 3  框架确认（7 大模块 + 场地 + 总则）
Step 4  逐模块起草 + 停下确认
Step 5  生成两个版本（原始版 / 现场填写版）
Step 6  渲染检查（标记/格式问题）
```

---

## 2. Step 1：源材料全读（动笔前必做）

先把所有已有的竞品底稿读完，按模块提取实测结论，再动笔。不要凭印象造框架。

典型底稿来源：
- 竞品横向对比梳理（`竞品对比-*.md`）
- 海外采集/现场测试记录（`20260502-五一假期竞品测试/`）
- 需求文档（`海外采集-定位专项需求文档.md`）
- 算法/产品规划讨论记录（`Eden_VSLAM算法规划梳理.md` 等）
- 历史测试 Case 定义（`Terramow测试Case.md` 等）

读完后建立「模块 → 竞品已知结论」的映射，写进每条用例的「已知参照」字段。

---

## 3. Step 2：竞品官方规格核查（定参数前必做）

在设置任何参数化测试条件（宽度、距离、档位、面积等）前，**先搜被测机官方声称值**，不用估值、不沿用其他竞品的标准。

本次案例：
- 窄通道宽度 → 搜到 Mova 官方声称「最小可通行 60cm」，据此将通道设为「约 60cm 挑战档 + 约 80cm 余量档」
- 刀盘宽度 → 官方 20cm，用于定量漏割示意图
- 爬坡/越障 → 40% / 4cm，写进官方能力声明表

信息源要标链接，便于后续核实（经销商页优先于二手转述，制造商官网最优）。

---

## 4. Step 3：框架确认

在起草正文前，先把以下结构确认清楚再动笔：

- **场地布置**：尺寸、分区（主草坪 / 副草坪 / 窄通道 / 共视过渡带 / 禁区 / 障碍物角）
- **7 大模块**：基础功能 / 重定位 / 搬桩 / 打滑 / 避障 / 高级功能 / 沿边距离（可根据机型增删）
- **总则**：光照档位 / 现象四档 / 重定位动作 ABCD 分类 / 回填字段

**不要加：** 工具清单、命名规范、模块编号（测试同事按自己习惯制表）

场地参数经验：
- 主草坪：18×18m（紧邻充电桩）
- 副草坪：≥8×8m（离桩远、与主区无视觉共视）
- 窄通道：长 ≥5m，宽以被测机官方最小通行宽度为参照

---

## 5. Step 4：逐模块起草 + 停下确认

**节奏**：每写完一个模块停下，给用户看，确认粒度/方向后再写下一模块。不要一口气写完再返工。

每条用例统一四段式：
```
前置：地图 / 桩 / 光照状态
步骤：可一次跑完的动作序列
观察点：本条要回答的问题（即回填项）
已知参照：竞品已测结论（用于现场判断"是否符合预期"）
```

**已知参照**的写法原则：
- 直接陈述结论，不出现跨文档引用字样（如 `[五一]` / `[xlsx]`），看的人不用再翻其他文档
- 只引用**同类传感器路线**的竞品（如纯视觉机只引 YUKA / Terramow，不引 RTK / LiDAR 机型）
- 标注「未测」或「待实测」而非留白或猜测

**重定位模块的关键原则**（纯视觉机特有）：
- 按**共视 / 环境纹理**组织（地图内 / 地图外有共视 / 地图外无共视），不按搬动距离组织
- 纯视觉机重定位成败强依赖共视，搬动距离只是表象，不单列「距离阈值」测试

当用户的纠偏指向一个通用 insight 时（不只是改这一条），把 insight 写进模块引言，让文档本身承载认知。

---

## 6. Step 5：生成两个版本

测试用例文档固定生成两个版本：

| 版本 | 文件名后缀 | 内容 | 给谁用 |
| --- | --- | --- | --- |
| **完整版（原始版）** | `*测试用例.md` | 含「已知参照」+ 竞品预期行为对照附录 | 测试负责人自留，用于对照分析 |
| **现场填写版** | `*测试用例-现场填写版.md` | 去掉「已知参照」/ 竞品实例 / 附录，只留前置+步骤+观察点 | 给现场测试同事，避免先入为主 |

清理现场填写版时需覆盖：
- 所有「已知参照」bullet
- §0 重定位动作分类表的「竞品实例/纯视觉实例」列
- 模块引言中点名竞品预期行为的句子（改成中性说明）
- 竞品预期行为对照附录（附录 A）
- 待补测清单（附录 B，含竞品具体信息）

---

## 7. Step 6：渲染检查

写完后对文档做渲染问题检查，常见坑：

- **单波浪号 `~` 误触发删除线**：同一行内成对的 `~`（如 `~25 m/min；~50–60 min`）会被 Markdown 渲染为删除线。修复：「约」义改成「约 X」，范围义改成 en-dash `a–b`
- **引用字样未清除**：搜 `[五一]` / `[xlsx]` / `[1月]` / `[K-` 等确认已全部替换为直接陈述
- **竞品名残留**（在现场填写版）：搜竞品名（Terramow / YUKA / 目芯 / i206 / i210 等）确认为零

---

## 8. 可选增强

- **定量测试项加示意图**：调头漏割 / 行间漏割等图示效果明显优于纯文字，可用 SVG 生成后嵌入
- **官方能力声明表前置**：被测机官方 spec 作为文档开头独立一节，包含信息源链接，作为测试「预期基线」
- **填写版标题注明**：文件名加 `-现场填写版` 后缀，标题页写明「本版为现场填写版，已移除竞品预期行为信息」
